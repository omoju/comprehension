# Chapter 5 · Cropping, the Buffer, and the Single Write

> **Enters as:** `new_segments == [Segment('Hello World!', Style(color=Color('red', ColorType.STANDARD, number=1), bold=True)), Segment('\n')]` — with the second string, `'Where there is a [bold cyan]Will[/bold cyan] there [u]is[/u] a [i]way[/i].'`, still waiting its turn

Two segments, a list, in memory. Nothing has been written yet. Between here and the file there are three gates: a crop, a buffer, and a single `write`.

## The crop

`print` skips the `new_line_start` branch ([`console.py#L1743-L1748`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1743-L1748)) — the caller left it `False` — and arrives at `if crop:` ([`L1749-L1756`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1749-L1756)). It looks up `self._buffer`, the thread-local list ([`L770-L773`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L770-L773)), which the trace shows as empty, and asks `self.width` for the cropping length. That property re-derives the size from scratch ([`L1056-L1063`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1056-L1063)); because `_width` was pinned in the constructor, whatever else `Console.size` consults, the final width it reports is the 100 the caller asked for ([`L1040-L1043`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1040-L1043)).

`Segment.split_and_crop_lines(new_segments, 100, pad=False)` ([`segment.py#L306-L351`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/segment.py#L306-L351)) accumulates the first segment, meets the `'\n'`, and hands the accumulated line — the text segment alone — to `adjust_line_length` ([`L353-L396`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/segment.py#L353-L396)). That function sums `segment.cell_length`, which is `0` for control segments and `cell_len(text)` otherwise ([`L78-L86`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/segment.py#L78-L86)), and the trace records the measurement: 12 cells. Twelve is less than a hundred, and `pad=False`, so the line is returned as a shallow copy, unchanged ([`L375-L379`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/segment.py#L375-L379)). Because `include_new_lines` defaults to `True`, a fresh `Segment('\n')` is appended ([`L344-L346`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/segment.py#L344-L346)), and the trace shows the yielded line: `[Segment('Hello World!', Style(...)), Segment('\n')]`. A second pull from the generator finds nothing left.

The branch not taken is the interesting one. Had the line measured more than 100 cells, `adjust_line_length` would have walked the segments accumulating width and cut the one that crossed the boundary with `set_cell_size` ([`L380-L393`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/segment.py#L380-L393)), discarding everything after it — and if the cut fell inside a double-width glyph, that glyph becomes spaces so the visible width still comes out exact.

> **For the owner:** This is the only unconditional enforcement of the console width. `ConsoleOptions.max_width` is advice that well-behaved renderables honour; `split_and_crop_lines` at `self.width` is the floor under them, and it runs for every line regardless of what produced it ([`console.py#L1749-L1754`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1749-L1754)). Passing `crop=False`, or `soft_wrap=True` which sets `crop = False` for you ([`console.py#L1695-L1702`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1695-L1702)), removes it — after that a third-party `__rich_console__` can emit lines wider than the terminal. Treat `soft_wrap` as switching off the width guarantee, not as a formatting preference.

## The buffer closes

The cropped line is extended into `self._buffer`, and the `with self:` block that has wrapped the whole of `print` since Chapter 2 now exits. `Console.__exit__` ([`L862-L864`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L862-L864)) calls `_exit_buffer`, which decrements `_buffer_index` from 1 to 0 and then calls `_check_buffer` ([`L817-L820`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L817-L820)).

`_check_buffer` ([`L2044-L2057`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2044-L2057)) has one early exit — if `self.quiet` were set, the buffer would be deleted and the output silently dropped — and otherwise calls `_write_buffer` inside a `try` that catches `BrokenPipeError`.

Inside `_write_buffer` ([`L2059-L2130`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2059-L2130)) the console takes its re-entrant lock and checks `self.record and not self._buffer_index` ([`L2063-L2065`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2063-L2065)). Both hold — the trace shows the index read as `0` and the buffer read immediately after — so a copy of exactly these two segments is appended to `_record_buffer` under a *separate* lock. The recording happens before the write and contains precisely what will be written.

Then `_buffer_index == 0` again ([`L2067`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2067)), not Jupyter, not Windows, so the data takes the short final branch ([`L2121-L2127`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2121-L2127)): render the buffer to a string, write it, flush, delete.

## Segments become a string

`_render_buffer` ([`L2132-L2154`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2132-L2154)) caches three decisions up front — the colour system (`None`), legacy Windows (`False`), and `not_terminal`, which the trace shows being computed as `is_terminal` returns `False`. Then one pass over the segments: a segment with a truthy style goes through `Style.render`; a styleless segment is appended verbatim *unless* it is a control segment on a non-terminal, in which case it is dropped ([`L2141-L2151`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2141-L2151)). That last clause is why piping Rich output to a file does not fill it with cursor-movement junk.

The red-bold style is truthy, so `Style.render('Hello World!', color_system=None, legacy_windows=False)` is called — and returns the text untouched, because the very first line of the method short-circuits on a `None` colour system ([`style.py#L710-L711`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/style.py#L710-L711)). This is where the question left open in Chapter 1 is settled: the style was parsed, cached, composed onto the segment, and carried the whole way here, and at the last step it costs nothing and produces nothing. The trace shows the return: `'Hello World!'`. Joined with the newline segment, `_render_buffer` gives back `'Hello World!\n'`.

`self.file` is resolved twice — once for `write`, once for `flush` — and `del self._buffer[:]` leaves the console clean for the next call.

> **For the owner:** Two guarantees and two failure modes live in this block. One `print` is one `write` plus one `flush`, taken under `self._lock`, so concurrent prints cannot interleave partial lines and a crash mid-render leaves nothing on screen rather than half a table. The failure modes are both loud: a `BrokenPipeError` is routed to `on_broken_pipe`, whose default sets `quiet`, redirects stdout to `/dev/null` and raises `SystemExit(1)` ([`console.py#L2030-L2042`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2030-L2042)) — override that method if your service must survive a closed pipe. A `UnicodeEncodeError` is re-raised with a `PYTHONIOENCODING` hint appended ([`console.py#L2125-L2127`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2125-L2127)). The quiet path is the only silent one: setting `Console.quiet` discards output without telling anyone ([`console.py#L2050-L2052`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2050-L2052)).

## The second string, and the tag parser

The trace folds the second `print` into a single line — the same path, the same gates — but one thing differs at the start of it. `'Where there is a [bold cyan]Will[/bold cyan] there [u]is[/u] a [i]way[/i].'` contains a `[`, so `markup.render` cannot take the fast path it used for `'Hello'` and `'World!'` ([`markup.py#L128-L132`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/markup.py#L128-L132)). It runs the parser.

`_parse` ([`markup.py#L73-L104`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/markup.py#L73-L104)) walks `RE_TAGS` and yields `(position, text, tag)` triples, handling backslash escapes on the way: an even number of backslashes becomes literal backslashes, an odd one escapes the following tag so it is emitted as text ([`L88-L98`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/markup.py#L88-L98)). `render` appends plain text to a growing `Text`, pushes each opening tag onto a stack paired with the current text length ([`L219-L221`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/markup.py#L219-L221)), and on each closing tag pops the matching entry and emits a `Span` over the enclosed range ([`L159-L217`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/markup.py#L159-L217)).

Both sides of a pair are passed through `Style.normalize` ([`style.py#L387-L402`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/style.py#L387-L402)), which round-trips the definition through `Style.parse`. That is why `[u]` matches `[/u]` and both become the span style `'underline'`, and why `[i]`/`[/i]` become `'italic'`. Tags still open when the string ends are closed silently at the full text length ([`markup.py#L223-L228`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/markup.py#L223-L228)); a closing tag with nothing to close is not silent — it raises `MarkupError` ([`L164-L176`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/markup.py#L164-L176)).

From there the three spans ride through `Text.render`'s style stack (the machinery described in Chapter 4), each becoming a `Segment` carrying a composed `Style` — and each of those styles, like the red-bold one before it, renders to nothing at the final step. The export at the end of the run confirms what landed: the recorded text begins `'Hello World!\nWhere there is a Will t…'`.

> **For the owner:** Markup is on by default for every string `print` and `log` touch. Any caller-supplied string containing `[...]` is *interpreted*: at best it injects styles you did not ask for, at worst an unbalanced tag turns a log line into a `MarkupError` raised from inside `print`. The two mitigations are `markup=False` (per call, or on the `Console` constructor) and `rich.markup.escape` ([`markup.py#L48-L70`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/markup.py#L48-L70)). Decide which one applies to every path where untrusted data reaches a console, and say so in review.

> **Leaves as:** `'Hello World!\n'` and then `'Where there is a Will there is a way.\n'` written to the file and flushed — each as one `write`, each copied into `_record_buffer` first, and `self._buffer` emptied after both
