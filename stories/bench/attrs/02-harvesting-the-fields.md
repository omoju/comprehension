# Chapter 2 · Harvesting the Fields

> **Enters as:** `_transform_attrs(cls, these=None, auto_attribs=True, kw_only=KeywordOnly.NO, collect_by_mro=True, field_transformer=None)` over a class whose `__dict__` holds `42`, a `Factory`, and a method

The `ClassProps` record from the last chapter is handed, along with the class itself, to `_ClassBuilder.__init__`. Before the builder assigns a single one of its own slots, it [calls `_transform_attrs`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L684-L691) with five of those settings unpacked. This is the only place where *attrs* reads the class body, and everything downstream — the `__init__` signature, the `__repr__`, the slots — is built from what comes back.

The first two lines of the function take the class apart: [`cd = cls.__dict__` and `anns = _get_annotations(cls)`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L399-L400). The trace records the annotation lookup returning `{'a_number': <class 'int'>, 'list_of_numbers': list[int]}`. On this interpreter that comes from the simple branch — [`cls.__dict__.get("__annotations__", {})`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_compat.py#L30-L34); on Python 3.14 and later the same call routes through [`annotationlib` in `FORWARDREF` format](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_compat.py#L17-L26) so that unresolvable forward references don't explode here.

Note what the two dicts disagree about. `cd` contains `42`, the `Factory`, *and* `hard_math`. `anns` contains only the two names that were annotated. In `auto_attribs` mode it is the annotations that decide: the loop [`for attr_name, type in anns.items()`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L411-L420) never looks at `hard_math`, and a plain unannotated class attribute would be equally invisible.

Each annotation is first screened by `_is_class_var`. The trace shows it called with `<class 'int'>` → `False` and with `list[int]` → `False`. The implementation is unapologetically a string comparison: it stringifies the annotation, strips surrounding quotes, and [tests `annot.startswith(_CLASSVAR_PREFIXES)`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L295-L310) against the four spellings `"typing.ClassVar"`, `"t.ClassVar"`, `"ClassVar"`, `"typing_extensions.ClassVar"` ([listed here](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L41-L46)). The docstring says why: evaluating every string annotation would put *attrs* classes at a performance disadvantage against plain classes.

> **For the owner:** ClassVar detection is textual, not semantic. An annotation written through an unrecognized alias — say `import typing as tp` and `tp.ClassVar[int]` — is not detected, and the member silently becomes an instance field with the class-body value as its default. Require one of the four recognized spellings in annotated *attrs* classes.

Surviving the screen, each name is looked up in the class body: [`a = cd.get(attr_name, NOTHING)`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L416-L419). Neither `42` nor the `Factory` is a `_CountingAttr`, so both are auto-wrapped by `attrib(a)` — which is exactly what the trace shows: `attrib(default=42, ...)` and `attrib(default=Factory(factory=<class 'list'>, takes_self=False), ...)`.

Inside `attrib`, `_determine_attrib_eq_order(None, None, None, True)` resolves `(True, None, True, None)` — equality on, ordering mirroring equality, no key functions — and then, because `factory` was `None` and `metadata` was `None`, the latter [becomes an empty dict](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L184-L185). A list or tuple passed as `validator`, `converter`, or `on_setattr` would have been wrapped here in [`and_` / `pipe` / `setters.pipe`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L188-L195); all three were `None`. What comes out is a [`_CountingAttr`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L197-L214) whose only job is to remember a definition order: the trace shows `counter=6` and `counter=7`, drawn from a [process-wide class counter](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L2828-L2829). In annotation mode the order is already fixed by the annotations dict; the counter matters for the non-annotated path, which sorts the class body by it.

This is also where the fallback promised in chapter 1 lives. After the loop, `_transform_attrs` computes `unannotated = ca_names - annot_names` and, if it is non-empty, raises [`UnannotatedAttributeError` listing the offenders](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L422-L430). That happens here, at the very top of the build, before the builder has written anything onto the class — which is why `define`'s `try/except` can simply re-enter with `auto_attribs=False` against a class that is still exactly as the user wrote it. `SomeClass` has no bare `field()`, so `unannotated` is empty.

Now the two `_CountingAttr`s are promoted. `Attribute.from_counting_attr('a_number', ca, kw_only=False, type=int)` — note the third argument: `_transform_attrs` passes [`kw_only is not no`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L441-L451), and since the class-level setting is `KeywordOnly.NO`, that is `False`. `from_counting_attr` then copies fifteen values across, resolving two of them by hand: the per-field setting wins over the class default via [`kw_only if ca.kw_only is None else ca.kw_only`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L2618-L2618), and `alias_is_default` is recorded as [`ca.alias is None`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L2624-L2625) — `True` here, because nobody asked for a specific `__init__` parameter name. (Had the user supplied both an annotation and `field(type=...)`, this method would have [raised a `ValueError`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L2601-L2605) rather than guess.)

`Attribute.__init__` writes every one of those values through [`bound_setattr = _OBJ_SETATTR.__get__(self)`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L2558-L2589) — because `Attribute` defines [`__setattr__` to raise `FrozenInstanceError`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L2591-L2592). The field descriptions that every validator, every `fields()` caller, and every third-party tool will later read are immutable by construction. The trace's nested `_determine_attrib_eq_order(cmp=None, eq=True, order=True, default_eq=True)` with its two `decide_callable_or_boolean` calls is just the same normalization run again on already-normalized values: a callable in `eq` would have [become `(True, that_callable)`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1293-L1301); a bare `True` stays `(True, None)`.

Next, inheritance. `_collect_base_attrs(cls, {'a_number', 'list_of_numbers'})` returns `([], {})` — `SomeClass` has only `object` behind it. The function it took is the correct one: it walks [`reversed(cls.__mro__[1:-1])`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L330-L338), skips anything already defined on this class or already marked `inherited`, and then [keeps only the furthest-back definition of each name](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L342-L349). `define` always routes here; the legacy forward-walking variant is reachable only through `attr.s` and will matter again in chapter 8.

Then the aliases. Any field without one gets `name.lstrip("_")`, and the write is done with the same frozen-bypass trick, with a comment that doesn't pretend otherwise — [*"Evolve is very slow, so we hold our nose and do it dirty"*](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L470-L476). The trace shows `_default_init_alias_for('a_number')` → `'a_number'` and the same for `list_of_numbers`; nothing is stripped because neither name starts with an underscore. Crucially this happens *before* the [`field_transformer` hook](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L477-L478), so a hook always receives fully populated `Attribute`s — and a [second alias pass afterwards](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L494-L499) catches any field the hook invented. Here `field_transformer` is `None`, so the attribute list passes through untouched.

Between the two alias passes sits the one rule *attrs* enforces on field order. It walks the fields that are `init is not False` and `kw_only is False`, and if a mandatory field follows one with a default, it raises [`ValueError: No mandatory attributes allowed after an attribute with a default value or factory`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L485-L489). Both of this class's fields have defaults, so the check passes silently.

> **For the owner:** A field ordering mistake — including one introduced by base-class inheritance or by a `field_transformer` — raises `ValueError` at class-definition time, which means at import time, not at the first instantiation. Treat that as a guarantee you can rely on: these classes cannot be imported in a broken state.

Finally the container. `_make_attr_tuple_class('SomeClass', ['a_number', 'list_of_numbers'])` builds [a bare `tuple` subclass with one `property` per field name](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L266-L284), returned in the trace as `<class 'attr._make.SomeClassAttributes'>`. It is created *after* the transformer precisely because the transformer may add or remove names. The two `Attribute`s are packed into it and returned as [`_Attributes(AttrsClass(attrs), base_attrs, base_attr_map)`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L503-L506) — a tuple you can index *and* reach into by name, which is what makes `attrs.fields(C).a_number` work.

The class body has now been fully read. Nothing has been written back to it yet.

> **Leaves as:** `_Attributes(attrs=(Attribute(name='a_number', default=42, type=int, alias='a_number', alias_is_default=True, kw_only=False, inherited=False), Attribute(name='list_of_numbers', default=Factory(factory=list, takes_self=False), type=list[int], alias='list_of_numbers')), base_attrs=[], base_attrs_map={})`, the pair wrapped in a generated `SomeClassAttributes` tuple subclass
