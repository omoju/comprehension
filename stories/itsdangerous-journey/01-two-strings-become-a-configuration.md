# Chapter 1 · Two Strings Become a Configuration

> **I arrive as:** `secret_key='secret key'`, `salt='auth'`, and five `None`s — `serializer`, `serializer_kwargs`, `signer`, `signer_kwargs`, `fallback_signers`

I begin as two ordinary Python strings sitting in a call: `URLSafeSerializer("secret key", "auth")`. Nothing about me is secret yet, nothing is bytes, nothing is signed. `URLSafeSerializer` itself defines no `__init__` — it is [a bare subclass of `URLSafeSerializerMixin` and `Serializer[str]`](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/url_safe.py#L72-L76) — so I am handed straight to [`Serializer.__init__`](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/serializer.py#L190-L202), with `serializer`, `serializer_kwargs`, `signer`, `signer_kwargs` and `fallback_signers` all left at `None`. Every one of those `None`s is a default about to be chosen on my behalf, and those defaults are the whole of what this object will guarantee later.

## The key is widened before it is used

The first thing that happens to my secret key is that it stops being one key. [`self.secret_keys = _make_keys_list(secret_key)`](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/serializer.py#L208-L208) hands `'secret key'` to [`_make_keys_list`](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/signer.py#L67-L73), which checks `isinstance(secret_key, (str, bytes))` and, since I am a `str`, wraps me: `[want_bytes('secret key')]` → `[b'secret key']`.

That is worth pausing on, because it is a design decision and not just plumbing. There is no "one key" code path and no "many keys" code path — there is only the list. A caller who passes `["old", "new"]` and a caller who passes `"secret key"` travel exactly the same road afterwards. The cost is that every later reader of `secret_keys` has to decide *which* key it means; the benefit is that key rotation is never a bolted-on special case.

The encoding step is [`want_bytes`](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/encoding.py#L11-L17): if it is a `str`, UTF-8 encode it; otherwise pass it through untouched. It is called with `errors='strict'`, so a key that cannot be UTF-8 encoded raises rather than being silently mangled. I go in as `'secret key'` and come out as `b'secret key'`.

The salt gets the same treatment, one line later: the constructor guards with `if salt is not None`, then [`salt = want_bytes(salt)`](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/serializer.py#L210-L214) turns `'auth'` into `b'auth'` and stores it. Had I been constructed with `salt=None`, that branch would have been skipped and the salt left as `None`, to be filled in later by the signer's own default — the comment on line 212 says exactly that. I took the other road: `self.salt = b'auth'`.

A word on what "salt" means here, because the name misleads. This is not a password-hashing salt. It is not random, it is not secret, and it will be stored in plain bytes and concatenated into key derivation. The docs are blunt about it: it ["doesn't have to be random, and can be saved in code. It only has to be unique between contexts, not private"](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/docs/concepts.rst#L59-L69). Its job is to make an activation token useless as an upgrade token. My salt is `b'auth'`, so I will only ever verify tokens minted for the `auth` context.

## The serializer is chosen — and then probed

`serializer` arrived as `None`, so [the constructor falls back to `self.default_serializer`](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/serializer.py#L216-L219). On a plain `Serializer` that attribute is [the stdlib `json` module](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/serializer.py#L92-L95), but I am a `URLSafeSerializer`, and `URLSafeSerializerMixin` [overrides it to `_CompactJSON`](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/url_safe.py#L21-L21). The trace confirms it: the class that turns up is `<class 'itsdangerous._json._CompactJSON'>`.

`_CompactJSON` is a thin wrapper that [sets `ensure_ascii=False` and `separators=(",", ":")`](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/_json.py#L14-L18) before delegating to `json.dumps`. No spaces after colons or commas, no `\uXXXX` escaping of non-ASCII. That matters because everything this serializer produces is destined for a URL or a cookie, where bytes are scarce.

Then comes the step a reviewer should notice, because it has a side effect. The next line is [`self.is_text_serializer = is_text_serializer(serializer)`](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/serializer.py#L220-L220), and [`is_text_serializer`](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/serializer.py#L33-L37) does not read a flag or inspect a type annotation. It *runs the serializer*:

```
_CompactJSON.dumps(obj={}) → '{}'
isinstance('{}', str)      → True
```

The trace shows that call plainly at line 12: `dumps({})` returning `'{}'`, and `is_text_serializer` returning `True`. This is a probe, not a declaration. Two consequences follow. First, a user-supplied serializer is invoked once, with `{}`, during construction — if someone's custom `dumps` has side effects or rejects empty dicts, they discover it at `__init__` time, not at `dumps` time. That is arguably the friendlier failure. Second, the answer is cached on the instance and is never re-checked; swapping `self.serializer` afterwards without updating `is_text_serializer` would put me in an inconsistent state.

What does that one boolean buy? I will not find out until chapter 4 — it is the switch that decides whether the token I eventually hand back is a `str` or `bytes`.

## The signer, and the fallbacks that aren't there

`signer` was `None` too, so [`self.signer` becomes `self.default_signer`](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/serializer.py#L222-L225), which on `Serializer` is [the plain `Signer` class](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/serializer.py#L97-L99). Note it stores the *class*, not an instance — no signer exists yet. `signer_kwargs` was `None`, so [`signer_kwargs or {}`](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/serializer.py#L226-L226) gives `{}`: whatever digest and key-derivation defaults `Signer` carries, I will inherit unmodified.

Finally the fallbacks. `fallback_signers` is `None`, so the constructor [copies `self.default_fallback_signers`](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/serializer.py#L228-L233) — and that class attribute is [an empty list](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/serializer.py#L101-L104). This used to not be empty: 1.1 shipped an implicit SHA-512 fallback for people affected by a yanked release, and [2.0 removed it](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/CHANGES.rst#L95-L96). So by default I will accept exactly one signing configuration and no other. That is the conservative choice — nothing silently validates against parameters you did not ask for — and it means anyone who wants to migrate digests has to say so explicitly. Note also the `list(...)` copy: my fallback list is mine, not shared mutable class state. `serializer_kwargs` gets the same `or {}` treatment on the [last line](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/serializer.py#L234-L234).

`__init__` returns `None`, and I am no longer two strings. I am a configuration: a one-element key list in bytes, a context salt in bytes, a compact-JSON text serializer known to produce `str`, a signer class not yet instantiated, and an empty set of fallbacks. Nothing has been signed. Nothing has been hashed. But every decision about *how* the signing will work has now been made and frozen on this object.

> **I leave as:** a configured `URLSafeSerializer` with `secret_keys=[b'secret key']`, `salt=b'auth'`, `serializer=_CompactJSON`, `is_text_serializer=True`, `signer=Signer`, `signer_kwargs={}`, `fallback_signers=[]`, `serializer_kwargs={}`
