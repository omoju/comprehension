# Chapter 4 · Markup.escape and the Reassembled Page

> **Enters as:** `Markup('<a href="/user/3"><span class="user">Alice &#34;The &lt;b&gt;Great&lt;/b&gt;&#34;</span></a>')`, returned by `User.__html_format__` into the outer `format_field`

The anchor fragment comes back to the line that started the whole detour. `format_field` holds it as `rv` and must now hand a string to the formatter. The last statement escapes that value first ([`__init__.py:354`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L354)). The trace records the call at line 45: `Markup.escape(cls=Markup, s=Markup('<a href="/user/3">…</a>'))`. This is the moment where a careless library would escape the anchor tag a second time and print it as visible text.

`Markup.escape` is a classmethod with 2 jobs ([`__init__.py:230-240`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L230-L240)). First it calls the module-level `escape` ([`__init__.py:235`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L235)). Second it compares `rv.__class__` with `cls` and re-wraps only when they differ ([`__init__.py:237-240`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L237-L240)). That comparison is how a `Markup` subclass keeps its own type through `escape`, `format`, `join` and `+`. In this run the class already matched, so the method returned the value from `escape` and allocated nothing more.

Inside `escape` the fragment took the second road, as the comment did in chapter 1. The anchor is a `Markup`, so `type(s) is str` is false and `_escape_inner` never ran ([`__init__.py:39-40`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L39-L40)). The `hasattr(s, "__html__")` test won instead ([`__init__.py:42-43`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L42-L43)). `Markup.__html__` returns `self` ([`__init__.py:133-134`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L133-L134)), and `Markup.__new__` checked for `__html__` once more before it wrapped the text ([`__init__.py:125-126`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L125-L126)). The trace shows both calls, at lines 47 and 50. The text came out character for character the same: the `<a>` and `<span>` tags stayed live, and the name inside them stayed inert.

> **For the owner:** This is the rule that makes nested fragments usable. Safe markup inside safe markup is never escaped twice. The price is that `escape` calls `__html__` twice for every object that defines it, once in `escape` and once in `Markup.__new__`. Warning: a `__html__` method with side effects or with high cost runs 2 times per call. Keep `__html__` implementations pure and cheap.

`format_field` then returned the plain string `'<a href="/user/3"><span class="user">Alice &#34;The &lt;b&gt;Great&lt;/b&gt;&#34;</span></a>'`, as trace line 55 shows. The formatter took that string and moved to the next field.

The `{comment}` field followed the same path, which the trace collapses into one line, `EscapeFormatter.format_field ×1 more` at line 56. The comment is a `Markup`, and `Markup` defines `__html_format__`, so the first test in `format_field` wins ([`__init__.py:340-341`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L340-L341)). The specifier is empty, so that method returns `self` ([`__init__.py:325-329`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L325-L329)). The final `escape` call then saw `__html__` again and passed the text through unchanged. The comment entered the page still as `&lt;script&gt;alert(document.cookie);&lt;/script&gt;`.

`string.Formatter.vformat` joined the trusted template text with the 2 field strings into one plain `str`. `Markup.format` wrapped that whole result with `self.__class__(...)` ([`__init__.py:313-315`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L313-L315)). Trace line 57 shows `Markup.__new__` receiving the joined text, and line 59 shows the page leaving `format` as a `Markup`. That final wrap is where the type-level guarantee returns after the plain-string work of chapter 3. The scenario then printed the value, and `Markup.__repr__` labelled it with the class name ([`__init__.py:167-168`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L167-L168)).

> **For the owner:** The page contains `&lt;script&gt;` and never `<script>`. The scenario's check `assert "<script>" not in page` holds by construction, not by inspection of the output. Note the limit of that statement. It applies to values that arrived through `escape`, `format`, `%`, `+` or `join`. It does not apply to the template text itself, which `Markup.format` trusts in full. Before you sign off, check that every `Markup(...)` call in the code base wraps a developer-written literal, not data from a request.

Format errors do not pass silently. A malformed field raises from `string.Formatter`, and the `%` path raises `TypeError` when an argument is missing ([`__init__.py:154-165`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L154-L165), pinned by [`tests/test_markupsafe.py:55-58`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/tests/test_markupsafe.py#L55-L58)). A render either completes or raises. It does not emit a half-built fragment.
