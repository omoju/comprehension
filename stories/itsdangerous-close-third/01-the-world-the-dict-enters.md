# Chapter 1 · The World the Dict Enters

> **Enters as:** `secret_key='secret key'`, `salt='auth'`, `serializer=None`, `serializer_kwargs=None`, `signer=None`, `signer_kwargs=None`, `fallback_signers=None`

The dict `{"id": 5, "name": "itsdangerous"}` is not here yet. It is one line away, waiting in `main()`, and before it can be handed over there has to be something to hand it to. That something is built in a single call — `URLSafeSerializer("secret key", "auth")` — and what happens inside decides almost everything the dict will experience later: how it will be written down, what key will vouch for it, and whether it comes back as text or bytes.

`URLSafeSerializer` has no body of its own; it is a name for the combination of a mixin and the base serializer ([url_safe.py](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/url_safe.py#L72-L76)), so construction lands in `Serializer.__init__` ([serializer.py](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/serializer.py#L190-L202)). Four decisions get made there, in order.

**The key becomes a list.** `'secret key'` goes to `_make_keys_list`, which sees a `str`, wraps it, and returns `[b'secret key']` ([signer.py](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/signer.py#L67-L73)). The encoding step is `want_bytes`, which encodes text as UTF-8 with `errors='strict'` ([encoding.py](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/encoding.py#L11-L17)) — so keys are always compared as bytes, never as text, and no locale or encoding surprise can make two "equal" keys differ. The one-element list is not a formality: it is the key-rotation mechanism collapsed to its simplest case. Had the caller passed `["old", "new"]`, the same function would have produced two entries, oldest to newest, and stored them on `self.secret_keys` ([serializer.py](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/serializer.py#L208)).

**The salt becomes bytes.** `'auth'` is not `None`, so it is run through `want_bytes` and stored as `b'auth'` ([serializer.py](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/serializer.py#L210-L214)). Passing `None` here would have been allowed too, and would have left the decision to the `Signer`'s own default later. The parameter's default, if the caller had given only a key, is `b"itsdangerous"`. Nothing cryptographic happens to the salt yet; it is just filed away.

> **For the owner:** The salt is not a second secret. It is a context label — `"auth"` here — that will be mixed into key derivation so that tokens minted for one purpose cannot be replayed into another. It may live in source code; the secret key may not. If you see a review where someone has swapped their roles (random salt, hardcoded key), that is the bug worth catching. The library's own docs are explicit that the salt "only has to be unique between contexts, not private" ([concepts.rst](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/docs/concepts.rst#L56-L69)).

**The serializer is chosen, then probed.** `serializer=None`, so the class attribute is used ([serializer.py](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/serializer.py#L216-L217)) — and because of the mixin, that attribute is not stdlib `json` but `_CompactJSON` ([url_safe.py](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/url_safe.py#L21)), a thin wrapper that defaults `separators` to `(",", ":")` and `ensure_ascii` to `False` ([_json.py](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/_json.py#L14-L18)). That is why the dict will come out as `{"id":5,...}` with no spaces: every byte saved is a byte the token does not have to carry through a URL.

Then something slightly unusual. The constructor calls `is_text_serializer(serializer)`, which does not ask the serializer what it produces — it *makes* it produce something: `serializer.dumps({})` and an `isinstance(..., str)` check ([serializer.py](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/serializer.py#L33-L37)). The trace shows exactly that throwaway call returning `'{}'`, and the answer `True` being remembered as `self.is_text_serializer` ([serializer.py](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/serializer.py#L219-L220)). It is a probe, not a declaration. A custom serializer that raised on an empty dict — or whose `dumps` had side effects — would misbehave at construction time rather than at first use. For `json` and `pickle`, the two cases the project tests, the probe is cheap and correct.

**The signer and its fallbacks.** `signer=None` means the class default, which for the plain serializer is `Signer` ([serializer.py](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/serializer.py#L222-L226)); `signer_kwargs=None` becomes `{}`. `fallback_signers=None` becomes a copy of `default_fallback_signers` ([serializer.py](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/serializer.py#L228-L233)), which since 2.0 is an empty list ([serializer.py](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/serializer.py#L101-L104)) — the old SHA-512 fallback was removed. So this serializer will accept exactly one shape of signature, and no legacy one.

Notice what did *not* happen. No hash was computed. No key was derived. `hashlib.sha1` was not even looked up: the default digest is `_lazy_sha1`, a function that defers the attribute access to call time precisely so that FIPS builds without SHA-1 don't explode at import, before a developer has had the chance to configure something else ([signer.py](https://github.com/pallets/itsdangerous/blob/672971d66a2ef9f85151e53283113f33d642dabd/src/itsdangerous/signer.py#L40-L45)). Construction is pure bookkeeping.

> **For the owner:** Two defaults here are worth a question before sign-off. First, the secret key: this constructor accepts a short human-typed string like `"secret key"` without complaint, and nothing downstream stretches it — key derivation is a hash concatenation, not a KDF. Whether the key is strong is entirely the caller's problem. Second, `fallback_signers=[]` means there is no migration path built in: if you later change the digest method or derivation scheme, every token already in the wild stops validating on the next deploy unless you add a fallback entry then. Both are defensible defaults; both are decisions someone should have made deliberately.

`__init__` returns `None`. What exists now is an object holding `secret_keys=[b'secret key']`, `salt=b'auth'`, `serializer=_CompactJSON`, `is_text_serializer=True`, `signer=Signer`, and empty dicts and lists for everything else — a set of rules, waiting. On the next line of `main()`, the dict arrives.

> **Leaves as:** a `URLSafeSerializer` with `secret_keys=[b'secret key']`, `salt=b'auth'`, `serializer=_CompactJSON`, `is_text_serializer=True`, `signer=Signer`, `signer_kwargs={}`, `serializer_kwargs={}`, `fallback_signers=[]`
