# Chapter 6 · Deciding who goes first, and the help option that was never passed

> **Enters as:** `({'count': '3'}, [], [<Option count>])` — the parser's dict, no leftover tokens, and the user's invocation order

The tuple lands back in `Command.parse_args`, which unpacks it into `opts`, `args` and `param_order` and then does something the dict has no say in: [it decides the order in which parameters will be processed, and loops over that order rather than over the dict](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L1396-L1400). The dict is a lookup table now, not a work list. Every declared parameter gets a turn, including the two that appear nowhere in it.

## The same three objects, again

[`get_params` is called a second time](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L1128-L1133) and returns `[<Option count>, <Option name>, <Option _click_default_help>]`. The help option is not rebuilt: [it was cached in `Command._help_option` the first time](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L1240-L1250), and the comment there says why — the ordering function about to run compares parameters by object identity, so a fresh instance each call would quietly break callback order.

[`iter_params_for_processing` sorts the declaration list with a two-part key](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L168-L192): `not item.is_eager` first, then the parameter's index in the invocation order, with [`float("inf")` for anything the user never mentioned](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L185-L190). `count` was mentioned and is not eager, so its key is `(True, 0)`. `name` was not mentioned and is not eager: `(True, inf)`. The help option is eager, so its key begins with `False` and it sorts ahead of both. The result is `[<Option _click_default_help>, <Option count>, <Option name>]`.

> **For the owner:** Eagerness is the mechanism behind the guarantee that `prog --help` and `prog --version` work even when a required option is missing — an eager callback can print and exit before any non-eager parameter is validated. If you write an option whose callback exits the program, mark it `is_eager=True`; otherwise a missing required parameter elsewhere will pre-empt it with a usage error.

## The parameter nobody typed goes first

[`handle_parse_result`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L2835-L2855) opens by photographing the slot this parameter is about to write: `ctx.params.get('_click_default_help', UNSET)` is `UNSET` because nothing has been stored yet, `ctx.get_parameter_source(...)` is `None`, and the explicit-default flag defaults to `False`. Those three readings matter only when several options share one storage name; they are taken now, before anything is mutated.

Then [the whole body runs inside `augment_usage_errors(ctx, param=self)`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L2857-L2858), a context manager that [catches `BadParameter` and `UsageError` on the way out and fills in the missing `ctx` and `param`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L149-L165). That is why a type failure raised deep inside a converter still names the option that caused it.

## Where a value comes from, in order

[`Option.consume_value` delegates first to `Parameter.consume_value`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L3726-L3738), which walks a fixed precedence. [The parser's dict is consulted first](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L2599-L2607): `opts.get('_click_default_help', UNSET)` misses, so the value is the `UNSET` sentinel and the source starts as `DEFAULT` rather than `COMMANDLINE`. Next [the environment variable](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L2609-L2613): `Option.resolve_envvar_value` finds no declared `envvar` and [returns `None` immediately](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L2799-L2800), then checks [`ctx.auto_envvar_prefix`, which is `None` here](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L3669-L3676) — so `os.environ` is never read at all. Next [the default map](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L2615-L2624); [`_default_map_has` answers `False`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L787-L799) because the context has no map.

That leaves the parameter's own default, and this is where the sentinel earns its keep. [`Parameter.get_default` returns the raw stored value, still `UNSET`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L2573-L2581). [`Option.get_default` hands it to `_resolve_lazy_default`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L3318-L3327), which sees a non-required boolean flag and [turns `UNSET` into `False`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L3239-L3243). Deriving that lazily, rather than writing `False` into `self.default` at construction time, is what keeps `default is UNSET` a truthful answer to "did the author pass a default?" — the question tie-breaks feature-switch groups later in this same method.

So `consume_value` returns `(False, ParameterSource.DEFAULT)`. Back in `handle_parse_result`, [the source is recorded on the context straight away](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L2860-L2863) — before conversion, before the callback — so that an eager callback can ask where its own value came from.

> **For the owner:** The precedence is command line, then environment variable, then `default_map`, then the parameter's default, and it is fixed; the chosen source is recorded and readable by your code as `ctx.get_parameter_source(name)`. Note that environment reading is opt-in per option via `envvar`, or globally via `Context.auto_envvar_prefix`; neither is set here, so no option in this command can be influenced by the environment.

[The deprecation branch is skipped](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L2865-L2879) — this option is not deprecated, and the branch would in any case only warn for a value the user actually supplied, since it requires a source more explicit than `DEFAULT_MAP`.

## Converting a value that came from nowhere

[`Option.process_value` has a shortcut for unset boolean flags](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L3782-L3794), but the value is already `False`, not `UNSET`, so it falls through [to `Parameter.process_value`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L3796-L3797). There `False` is [run through the parameter's type](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L2726-L2730): `nargs == 1`, so [a single-value converter is built](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L2657-L2660) and `BoolParamType` is called, whose [`str_to_bool` returns a `bool` unchanged](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/types.py#L866-L868). `False` survives as `False`. The option is not required, so [the missing-value check passes](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L2732-L2733).

And then the callback runs — [for a parameter the user never passed](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L2735-L2745). `ctx.params` is still empty, so there are no `UNSET` values to mask and the plain call is taken. [`show_help` receives `value=False`, fails its `if value and not ctx.resilient_parsing` guard, and returns `None`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/decorators.py#L612-L616). The callback's return value replaces the value, so what comes out of `process_value` is `None`.

Had conversion raised, [the surrounding `except` would re-raise in normal mode and reset the value to `UNSET` under resilient parsing](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L2881-L2890) — so a bad value can never stop `--help` or shell completion from working.

> **For the owner:** Every parameter's callback fires on every run, including for parameters the user did not supply; the callback is handed the default (or `None`) rather than being skipped. Write callbacks so that the "not provided" case is a no-op, as `show_help` does with its leading truthiness check.

## Winning a slot and then declining it

Finally, [the arbitration](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L2892-L2919). The snapshot said the slot was empty, so `slot_empty` is true and this option is the winner. But [writing the value is conditional on `expose_value`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L2909-L2912), and the help option was built with `expose_value=False`: nothing is written. `ctx.params` is still `{}`. The recorded source stays `DEFAULT`.

That is also why the storage name is the reserved `_click_default_help` rather than `help` — [a name no user parameter is expected to claim](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L59-L61), so a command with its own `help` parameter cannot clobber the slot.

[`handle_parse_result` returns `(None, [])`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L2921) — a value that goes nowhere and the unchanged leftover args. The loop turns to `count`, which is the first parameter the user actually typed.

> **Leaves as:** processing order `[_click_default_help, count, name]`; the help option resolved to `False`, converted, its callback run and its result `None` discarded; `ctx.params == {}` and `ctx.get_parameter_source('_click_default_help') is ParameterSource.DEFAULT`
