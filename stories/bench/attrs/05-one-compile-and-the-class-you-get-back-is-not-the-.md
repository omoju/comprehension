# Chapter 5 · One compile(), and the Class You Get Back Is Not the Class You Wrote

> **Enters as:** three queued snippets — `(repr_script, repr_globs, _attach_repr)`, `(eq_script, {}, _attach_eq)`, `(init_script, init_globs, _attach_init)` — plus a `_cls_dict` already holding `__attrs_attrs__`, `__attrs_props__`, getstate/setstate, `__ne__`, `__hash__ = None`, `__replace__` and `__match_args__`

`attrs.wrap` has nothing left to decide. It calls [`builder.build_class()`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L800-L821), and the first thing that happens is the moment all three scripts have been waiting for.

## One compile, one namespace

[`_eval_snippets`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L782-L798) joins the snippets with newlines into a single source string and merges every snippet's globs dict into one. The trace shows the result: a script that begins `def __repr__(self):\n  try:\n    alre…` and ends `…s = __attr_factory_list_of_numbers()\n`, and a globs dict carrying `AttributeError`, `Factory`, `NOTHING`, `_SRC`, `__attr_factory_list_of_numbers`, `__builtins__` — the repr snippet's helpers and the init snippet's factory and module namespace, now indistinguishable from each other.

That merge is worth pausing on. There is one namespace for all generated methods on a class, not one per method. A name injected for the initializer is visible to `__repr__` and `__eq__` as well.

[`_generate_unique_filename(cls, "methods")`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1634-L1641) produces `'<attrs generated methods __main__.SomeClass>'`, and [`_linecache_and_compile`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L231-L263) registers the source under that name in `linecache.cache` as the tuple `(len(script), None, script.splitlines(True), filename)`. This is why a debugger can step into `SomeClass.__init__` and why a traceback from it shows real source lines instead of `<string>`. If the name is already taken by a *different* source, [the loop appends a counter](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L246-L259) until it finds a free one — two classes with the same qualname don't overwrite each other's debug source.

Then [`_compile_and_eval`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L217-L228): `compile(script, filename, "exec")` followed by `eval(bytecode, globs, locs)`. One `compile` and one `eval` for the whole class. The trace records what came back in `locs`:

```
{'__eq__': <function __eq__>, '__init__': <function __init__>, '__repr__': <function __repr__>}
```

Three real functions, built from strings attrs assembled out of field names.

> **For the owner:** attrs interpolates field names directly into the source text it compiles, with no identifier check — `make_class` [states in its own docstring](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L3276-L3281) that validating names is the caller's duty, and [the initializer is built by f-string](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L2442-L2448). Validate any field names that arrive from outside your own source before passing them to `make_class` or to `these`.

The three attach hooks then run in registration order. [`_attach_repr`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1007-L1008) pulls `globs["__repr__"]`, stamps it via `_add_method_dunders_unsafe` — the trace shows the same address `0x10e15c400` going in bare and coming out as `<function SomeClass.__repr__>` — and writes it into `cls_dict`. Then [`_attach_eq`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1155-L1156), then [`_attach_init`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1101-L1104), which also sets `init.__annotations__` to the dict chapter 4 built. You can watch the dict fill up across trace lines 115, 119 and 123.

## A different class

`self._slots` is `True`, so [`build_class` takes the replacement branch](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L806-L809) rather than patching in place. `__slots__` cannot be added to a class after creation, so [`_create_slots_class`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L859-L1002) builds a new type.

It starts from [a copy of the class dict minus the field names, `__dict__` and `__weakref__`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L863-L867) — the `42` and the `Factory(list)` that sat in the body are dropped here, because slots will occupy those names. On 3.14 and later it also [clears the original type's descriptors](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L869-L871). It [walks the MRO for inherited slots and an existing `__weakref__`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L890-L902) — empty here, the only base is `object` — and so [appends a weakref slot](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L906-L913). Only [names not inherited from a base](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L946-L948) are slotted, and slots a base already defines are [re-bound from the collected descriptors instead of redefined](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L950-L960), so a parent's descriptor isn't shadowed by an empty one. The result is `cd["__slots__"] = ('a_number', 'list_of_numbers', '__weakref__')`, `cd["__qualname__"] = 'SomeClass'`, and then [`type(self._cls)(self._cls.__name__, self._cls.__bases__, cd)`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L968-L969).

Had the class carried a `functools.cached_property`, this is where its name would have been slotted and [a generated `__getattr__`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L915-L944) installed to compute and cache it — the documented crime against nature that makes `cached_property` work without a `__dict__`. `SomeClass` has none.

The last thing `_create_slots_class` does is the repair work the swap makes necessary. A method that mentions `__class__` or calls bare `super()` carries a closure cell baked by the compiler, and that cell points at the class being discarded. So attrs [walks the new class's dict — unwrapping classmethods, staticmethods and properties — and overwrites any cell whose contents are the old class](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L971-L1001).

Back in `build_class`, the old class gets [`__attrs_base_of_slotted__ = weakref.ref(cls)`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L808-L809) — a weak pointer from the discarded original to its replacement. Then [an *inherited* `__attrs_init_subclass__` would be called](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L813-L819); there is none. The new class is returned, and the trace shows it bubbling up unchanged through `build_class` → `wrap` → `do_it` → `wrap` → `define`, five returns of `<class '__main__.SomeClass'>`, until the name in the scenario module is bound to it.

> **For the owner:** With `slots=True` — the default for `@define` — the object bound to your class name is not the object the decorator received, which is why the *attrs* documentation records that [`object.__init_subclass__` misbehaves and the dead original lingers in `type.__subclasses__` until a garbage collection](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/docs/glossary.md#L96-L101). Do not keep references to the class from inside another decorator or a metaclass hook; use `__attrs_init_subclass__` instead of `__init_subclass__`.

## The silence afterwards

The scenario now builds `sc = SomeClass(1, [1, 2, 3])`, reprs it, calls `hard_math(3)` for `19`, builds a twin and compares them with `==`. The trace shows **nothing** for any of that. Those methods are compiled functions living on the class, not library calls into `attr`; the only reason `__ne__` appears at all is that it was never generated — [it is a plain module-level function](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1730-L1739) assigned straight onto the class.

So `sc != SomeClass(2, [3, 2, 1])` lands in `__ne__`, which calls `self.__eq__(other)`. Both operands are `SomeClass`, so the generated `__eq__` passes its class-identity guard, compares `1 == 2`, short-circuits, and returns `False`. `__ne__` sees a real boolean rather than `NotImplemented`, negates it, and returns `True` — trace line 137. A foreign operand would have travelled the other road: `__eq__` returning `NotImplemented`, `__ne__` forwarding it unchanged, and Python falling back to identity.

> **For the owner:** All per-class work — compiling, slotting, closure repair — happens once at import time, and the guarantees it establishes are then inert machine code on the class. Budget the cost against process startup, not against instance throughput.

> **Leaves as:** a new `<class '__main__.SomeClass'>` with `__slots__ = ('a_number', 'list_of_numbers', '__weakref__')`, `__repr__`/`__eq__`/`__init__` sharing one globals dict and one linecache entry at `<attrs generated methods __main__.SomeClass>`, bound to the scenario's module name; `sc = SomeClass(a_number=1, list_of_numbers=[1, 2, 3])`; and `sc != SomeClass(2, [3, 2, 1])` → `True`
