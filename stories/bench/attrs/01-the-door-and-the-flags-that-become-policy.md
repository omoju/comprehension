# Chapter 1 · The Door, and the Flags That Become Policy

> **Enters as:** `class SomeClass` with annotations `a_number: int = 42` and `list_of_numbers: list[int] = Factory(list)`, handed to `@define` as `maybe_cls`

Before the class exists, one small object is made ready for it. The expression `Factory(list)` in the class body runs first, and all it does is remember: [`self.factory = factory; self.takes_self = takes_self`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L3105-L3107). No list is created. `list` is stored as a callable, `takes_self` as `False`, and the object sits in the class body as a stand-in for "ask me later." That "later" is six chapters away.

Then Python finishes the class body, builds a plain type object named `SomeClass` with two annotations, one integer, one `Factory`, and one method, and hands it to the decorator.

`define` catches it as `maybe_cls` and immediately passes it to its inner `wrap` ([`return wrap(maybe_cls)`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_next_gen.py#L424-L427)). Everything that happens now happens exactly once, at import time, and the choices made here are frozen into the class for the rest of the program's life.

The first thing to notice is what the class *didn't* bring with it. The trace shows `define` called with `slots=True, auto_exc=True, auto_detect=True, order=False, force_kw_only=False` — not because the caller asked, but because those are the [signature defaults of `define`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_next_gen.py#L23-L47). The modern API is a different set of policies wearing the same machinery as `attr.s`.

`wrap` starts by rewriting one of its own arguments. The caller passed `on_setattr=None`, and the class is not frozen, so [`on_setattr = _DEFAULT_ON_SETATTR`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_next_gen.py#L399-L401) — which is [`setters.pipe(setters.convert, setters.validate)`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L57-L57). That is the `<function pipe.<locals>.wrapped_pipe>` you see threaded through the rest of the trace. The default for a mutable *attrs* class is that assignment after construction re-runs converters and validators, not just `__init__`.

Next `wrap` looks upward. It walks `cls.__bases__` and checks whether any of them has `__setattr__ is _frozen_setattrs`; if so, the subclass inherits immutability and `on_setattr` is forced to `NO_OP`. But if the caller had *also* asked for a hook, that combination raises instead of silently winning: [`"Frozen classes can't use on_setattr (frozen-ness was inherited)."`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_next_gen.py#L405-L412). `SomeClass` inherits from `object`, so this loop finds nothing and the convert-and-validate hook stands.

> **For the owner:** Mutable classes built with `@define` run converters and validators on *every* attribute assignment, not only in `__init__`. If you need plain assignment semantics for performance or for a field whose setter must not be re-validated, pass `on_setattr=None` or `attrs.setters.NO_OP` explicitly.

Then comes the guess. `auto_attribs` was left at `None`, so *attrs* does not ask — it tries: [`try: return do_it(cls, True) except UnannotatedAttributeError: return do_it(cls, False)`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_next_gen.py#L414-L420). The entire class build is the thing inside the `try`. This class is fully annotated, so the first attempt succeeds and the fallback never runs; the question of whether a half-built class can escape the failed attempt belongs to the next chapter, where the exception is actually raised.

`do_it` is a translation layer. It forwards everything to the classic [`attrs()`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_next_gen.py#L362-L387) and hard-codes one thing the old API leaves off by default: `collect_by_mro=True`. Users of `@define` never get the legacy base-class ordering bug.

Inside `attrs`, the class is still just an argument. `_determine_attrs_eq_order(None, None, False, None)` returns `(None, False)` — `eq` stays undecided because its default is `None` here, while `order=False` is already settled ([lines 1266-1281](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1266-L1281)). Then `attrs.wrap` runs the interrogation the trace records step by step:

- `_has_frozen_base_class(cls)` → `False`: [the check is literally `cls.__setattr__ is _frozen_setattrs`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1626-L1631).
- `_has_own_attribute(cls, "__setattr__")` → `False`, so there's no custom setter to collide with.
- `_determine_whether_to_implement(cls, None, True, ("__eq__", "__ne__"))` → `True`. With a `None` flag and `auto_detect=True`, this [loops over the dunders and asks `_has_own_attribute`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1339-L1350), which is nothing more than [`attrib_name in cls.__dict__`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L313-L317) — the class's *own* dict, not its MRO.
- `_has_own_attribute(cls, "__hash__")` → `False`, and then the hashability ladder: `hash` is `None`, the class defines no `__hash__`, `eq` is True but `is_frozen` is False, so the result is `Hashability.UNHASHABLE` ([lines 1506-1518](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1506-L1518)).
- Three more `_determine_whether_to_implement` calls settle `added_repr`, `added_ordering` (gated by `order_ = False`), and `added_pickling`, whose default is `slots` — [`default=slots`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1553-L1559) — so a slotted class gets `__getstate__`/`__setstate__` unless it defines its own.

> **For the owner:** `auto_detect` only looks at the decorated class's own `__dict__`. A hand-written `__eq__`, `__init__`, or `__hash__` on a *base* class does not stop *attrs* from generating and attaching its own on the subclass. Check inheritance hierarchies explicitly when you rely on a base class's dunder behaviour.

All of that collapses into one object. `ClassProps.__init__` takes sixteen positional settings and [assigns them straight to slots](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L3020-L3054). The trace's final call in this span is `ClassProps.is_hashable` → `False`, consulted by the guard that [rejects `cache_hash=True` on a non-hashable class with a `TypeError`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1564-L1566) before a single method is written. `cache_hash` was `False`, so the road is clear.

The class has not been touched yet. What exists is a record of intent — and *attrs* keeps it: the builder will stamp it onto the class as `__attrs_props__`, which is exactly what [`attrs.inspect()`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_next_gen.py#L674-L678) hands back to anyone who wants to audit what a decorated class actually agreed to.

> **For the owner:** Use `attrs.inspect(TheClass)` in review to read back the sixteen effective settings rather than inferring them from the decorator call. Note that `inspect` is documented as experimental and outside the project's backwards-compatibility guarantee, so do not build production logic on it.
