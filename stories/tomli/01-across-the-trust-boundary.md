# Chapter 1 · Across the trust boundary

> **Enters as:** `__s = '\n[[players]]\nname = "Lehtinen"\nnumber = 26\n\n[[players]]\nname = "Numminen"\nnumber = 27\n'`, `parse_float=<class 'float'>`

The string arrives at the only door Tomli opens to the world. `tomli.loads` is eight lines of re-export away from `_parser.loads` ([`__init__.py`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/__init__.py#L5-L8)), and the function it lands in is small enough to read in one breath. What happens in the first few lines decides what kind of object the rest of the parser is allowed to assume it has.

The first thing done to the string is not parsing at all. It is a rewrite: `src = __s.replace("\r\n", "\n")` ([`_parser.py#L169-L174`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L169-L174)). The comment above it says the spec permits converting `\r\n` to `\n` *even in string literals*, and Tomli takes that permission to simplify everything downstream: from here on, no code in the parser needs to consider a carriage return as a line ending. Our string has no `\r\n` in it, so `replace` hands back an equal copy, 87 characters long, and the parser proceeds with a value that is byte-for-byte what the caller wrote.

That `replace` call is also the type check. It sits inside a `try`, and an `AttributeError` or `TypeError` from it is converted into `TypeError(f"Expected str object, not '{type(__s).__qualname__}'")` with `from None` to suppress the misleading inner traceback. Hand `loads` a `bytes` object and you get "Expected str object, not 'bytes'"; hand it `False` and you get "not 'bool'". The parser never gets to run on a non-string. The sibling entry point `load` enforces the companion rule for files: it reads the file object and calls `.decode()`, and an `AttributeError` there becomes `TypeError("File must be opened in binary mode, e.g. use `open('foo.toml', 'rb')`")` ([`_parser.py#L152-L161`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L152-L161)).

> **For the owner:** Binary mode for `load` is a correctness requirement, not a style preference. Text mode would let Python apply universal newlines and a locale-dependent encoding before Tomli ever sees the bytes, which is why the code raises `TypeError` instead of guessing. Check that every `tomli.load` call site in your codebase opens with `"rb"`.

Now the world the string is about to enter gets built, and all of it is local. `pos = 0`. `out = Output()`. `header: Key = ()` — the empty tuple, meaning "the document root" ([`_parser.py#L175-L178`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L175-L178)).

`Output.__init__` is two assignments ([`_parser.py#L327-L330`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L327-L330)), and the trace shows both constructors running in turn. `NestedDict.__init__` creates `self.dict = {}` — the dictionary that will, eighty-odd characters later, be handed back to the caller as the result ([`_parser.py#L293-L296`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L293-L296)). `Flags.__init__` creates `self._flags = {}` and `self._pending_flags = set()`, the bookkeeping that will later decide which table names may be declared, redeclared, or mutated ([`_parser.py#L244-L246`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L244-L246)). Both start empty. Nothing in this module holds mutable state at import time; two threads calling `loads` at the same time build two independent `Output` objects and never see each other.

Then the second argument gets its one moment of attention. `parse_float = make_safe_parse_float(parse_float)` ([`_parser.py#L178`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L178)). The trace records the call and its return on the next line: `make_safe_parse_float(<class 'float'>) → <class 'float'>`. The same object came back out. That is deliberate — the function's first statement is `if parse_float is float: return float`, with the comment "The default `float` callable never returns illegal types. Optimize it." ([`_parser.py#L791-L793`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L791-L793)).

The rest of that function is what a *non*-default caller gets, and it is the reason the parameter is safe to expose at all. For any other callable, `make_safe_parse_float` returns a closure that calls the user's function and then checks the result: `if isinstance(float_value, (dict, list)): raise ValueError("parse_float must not return dicts or lists")` ([`_parser.py#L795-L801`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L795-L801)). A `parse_float` that returned a dict would inject a value into the output tree that the parser could not distinguish from a parsed TOML table, confusing its own bookkeeping — so the check happens at the boundary, eagerly, rather than producing a quietly wrong document.

> **For the owner:** `parse_float` is the one place where caller-supplied code runs inside the parse. The guard rejects only `dict` and `list` and their subtypes; it does not sandbox anything else, so an exception raised by your `parse_float` propagates out of `loads` as-is, not as a `TOMLDecodeError`. If you pass something other than `float` or `decimal.Decimal`, wrap your own error handling around the `loads` call.

With that, the string is no longer an argument: it is `src`, a validated `str`, paired with an integer cursor at 0, an empty result dict, an empty flag store, and a root header. The statement loop begins. Its very first act is `pos = skip_chars(src, pos, TOML_WS)` ([`_parser.py#L184`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L184)), which walks forward while the character is a space or a tab and stops otherwise, swallowing the `IndexError` at end-of-string rather than treating it as an error ([`_parser.py#L333-L339`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L333-L339)). Our document begins with a newline, not whitespace, so the call returns 0 unchanged. The loop reads `src[0]`, finds `"\n"`, advances to 1 and continues ([`_parser.py#L198-L200`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L198-L200)); the trace's second, elided `skip_chars` is the same no-op at position 1.

Now `src[1]` is `"["`. The loop peeks at `src[2]` inside a `try/except IndexError` — a lone trailing `[` would leave `second_char = None` rather than crash — and before dispatching, calls `out.flags.finalize_pending()` ([`_parser.py#L204-L213`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L204-L213)). The trace shows it returning `None` having done nothing: `_pending_flags` is still the empty set it was born with, so the loop over it has no iterations ([`_parser.py#L251-L254`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L251-L254)). It matters later; here it is a formality.

`second_char == "["`, so the road leads to `create_list_rule`. Had there been a single bracket, `create_dict_rule` would have taken the string instead, with a stricter rule about declaring the same name twice — but that is the next chapter's business.
