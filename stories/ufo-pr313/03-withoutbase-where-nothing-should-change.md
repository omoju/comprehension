# Chapter 3 · withoutBase, where nothing should change

> **Before:** Thirteen paths pass through `withoutBase` — some trimmed of a real base (`/base/a` minus `/base` → `/a`), some respecting a query boundary (`/api?test` minus `/api` → `/?test`), some left whole because they never matched (`/bar` minus `/foo` → `/bar`) or because the base was empty or the input had a protocol.
> **After:** Every one of them comes back with exactly the same value; the new boundary guard runs but never changes an answer.

Now the data turns to the other function. `withoutBase` is the inverse of `withBase`: instead of adding a missing base, it strips a present one. Thirteen cases flow through it in this span, and the reviewer's question is whether the new lookahead — the same idea as chapter 2, placed inside `withoutBase` — disturbs any of them. It does not, and here is why for each shape.

The first door is `isEmptyURL(base)`. For `/`-`/`, `/test/`-`/`, `/?test`-`/`, and `https://test.com`-`/`, the base is `/`, so [`withoutBase` returns the input immediately](https://github.com/unjs/ufo/blob/cb6af4e5e55fc21b5b776fd13b2d1e372f71f40c/src/utils.ts#L318-L321) — `/`, `/test/`, `/?test`, and `https://test.com` respectively (trace 117–119, 180–182, 187–189, 208–210). This door is [untouched by the change](https://github.com/unjs/ufo/blob/5fb179d51384301ffb66b48e213863a27cadd1ff/src/utils.ts#L315-L317), so the values match the base run exactly.

The second door is `!input.startsWith(_base)`. For `/`-`/foo`, `/`-`/foo/`, `/bar`-`/foo`, and `https://test.com`-`/base/`, `_base` is `/foo`, `/foo`, `/foo`, and `/base`, and the input never begins with those strings, so [the function returns the input unchanged](https://github.com/unjs/ufo/blob/cb6af4e5e55fc21b5b776fd13b2d1e372f71f40c/src/utils.ts#L322-L325): `/`, `/`, `/bar`, and `https://test.com` (trace 124–126, 131–133, 138–140, 201–203). The new guard sits *after* this door, so a non-match never reaches it; both sides agree.

The cases that do get past both doors are the genuine prefixes, and this is where the new `nextChar` check actually runs. For `/base/a` minus `/base`, `_base` is `/base`, `input.startsWith("/base")` is true, and `nextChar = input[5]` is `/`. [The guard `nextChar && nextChar !== "/" && nextChar !== "?"`](https://github.com/unjs/ufo/blob/cb6af4e5e55fc21b5b776fd13b2d1e372f71f40c/src/utils.ts#L326-L330) is false because `nextChar === "/"`, so control falls through to the slice: `input.slice(5)` is `/a`, whose first character is `/`, so it returns `/a` (trace 159–161). The base run had no guard and reached the same slice, giving the same `/a` (trace 158). The twin case `/base/a` minus `/base/` behaves identically — `withoutTrailingSlash` turns the base into `/base` too, so `nextChar` is again `/` and the result is again `/a` (trace 166–168).

Two more prefixes land on the boundary characters the guard was written to accept. For `/base`-`/base/`, `_base` is `/base`, and `nextChar = input[5]` is `undefined` (the string ends there); the guard's leading `nextChar &&` short-circuits to false, the slice yields `""`, and the leading-slash step returns `/` (trace 145–147). For `/api?test`-`/api`, `nextChar = input[4]` is `?`; the guard's `nextChar !== "?"` arm fails, so it falls through, slices to `?test`, and prepends a slash to give `/?test` (trace 194–196). The `?` boundary is exactly the query case the fix preserves — on the base run, with no guard, the slice produced the same `/?test` (trace 193).

So across all thirteen cases the guard runs on four of them and declines to act on every one, because in each the character after the base is `/`, `?`, or absent. The outputs are identical to the base run, line for line.

> **For the reviewer:** These thirteen cases are the preserved half of the evidence for `withoutBase`; the two genuinely-changed cases (`/admin-dashboard` against `/admin`) come in the next span. Note that the `?` boundary is load-bearing here: the `/api?test` → `/?test` result survives only because the guard treats `?` as a real boundary, so keep that character in the accepted set if you refactor it.
