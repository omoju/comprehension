# Chapter 2 · Reading the header name

> **Enters as:** `src`, `pos=1` — the cursor on the first `[` of `[[players]]`, with `src[2]` confirmed to be `[` as well

`create_list_rule` takes the string, the cursor, and the `Output` it will eventually write into, and its first line is the shortest possible acknowledgement of what the loop already knew: `pos += 2  # Skip "[["` ([`_parser.py#L405-L406`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L405-L406)). The brackets are not re-checked. The caller's two-character peek was the whole check, and from here the cursor sits at 3, on the `p` of `players`.

Then `skip_chars(src, 3, TOML_WS)` ([`_parser.py#L407`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L407)) — the same whitespace walker from the statement loop, swallowing spaces and tabs. The trace records it returning 3: there is nothing between the brackets and the name. This call is why `[[ players ]]` and `[[players]]` are the same header; TOML allows the padding, and Tomli discards it before the name is ever read.

Now `parse_key(src, 3)` ([`_parser.py#L408`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L408)). This is the same function that will later read `name` and `number` on the left of an `=`; table headers and key/value pairs share one key grammar, so whatever is legal in one place is legal in the other.

`parse_key` immediately delegates the first segment to `parse_key_part` ([`_parser.py#L478-L480`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L478-L480)), which reads one character and chooses a road ([`_parser.py#L500-L513`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L500-L513)). The character is `p`, a member of `BARE_KEY_CHARS` — the frozenset of ASCII letters, digits, hyphen and underscore ([`_parser.py#L66-L68`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L66-L68)). So the bare-key branch runs: remember `start_pos = 3`, call `skip_chars` a third time, now with `BARE_KEY_CHARS` as the alphabet, and slice.

The trace shows that walk stopping at 10 — the `]` is not a bare-key character — and `parse_key_part` returning `(10, 'players')`. The name was never built character by character; it is one slice, `src[3:10]`.

Two roads were not taken there. A `'` would have gone to `parse_literal_str` ([`_parser.py#L509-L510`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L509-L510)) and a `"` to `parse_one_line_basic_str` ([`_parser.py#L511-L512`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L511-L512)) — which is how `["key#group"]` and `[a.'"b"'.c]` are legal, and how an empty key `""` is legal too. Anything else — a space, a bracket, a non-ASCII letter — falls through to `raise TOMLDecodeError("Invalid initial character for a key part", src, pos)` ([`_parser.py#L513`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L513)).

> **For the owner:** Table and key names are not restricted to anything resembling identifiers. Quoted parts may contain spaces, dots, `#`, control-ish characters and the empty string, and they arrive in the returned dict as literal `str` keys. Do not assume keys from an untrusted TOML file are safe to splice into paths, SQL, or attribute lookups.

Back in `parse_key`, the part is wrapped into a one-element tuple — `key: Key = (key_part,)` — and that tuple, not a dotted string, is the parser's name for a namespace from here on ([`_parser.py#L479-L480`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L479-L480), type `Key = Tuple[str, ...]` in [`_types.py#L9`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_types.py#L9)). Tuples of `str` compare and hash by content, which is exactly what the flag bookkeeping in the next chapter needs.

Then whitespace is skipped again — the trace's `skip_chars(src, 10, TOML_WS) → 10` — and the loop asks whether the next character is a `.` ([`_parser.py#L481-L492`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L481-L488)). It is `]`. So the loop ends on its first iteration and `parse_key` returns `(10, ('players',))`.

Had it been a dot, the loop would have consumed it, skipped more whitespace, parsed another part, and appended it — `[ g . h . i ]` and `[a.b.c]` reach the same three-element tuple. That loop carries one guard worth naming: after each append, `if len(key) > MAX_KEY_PARTS: raise RecursionError(f"TOML key has more than the allowed {MAX_KEY_PARTS} parts")` ([`_parser.py#L493-L496`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L493-L496)). `MAX_KEY_PARTS` is `sys.getrecursionlimit()`, and the comment above it states why: an excessive number of key parts "runs into quadratic behavior (e.g. in `Flags.is_`)", and although keys are not parsed recursively they name a recursive structure ([`_parser.py#L45-L50`](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/src/tomli/_parser.py#L45-L50)). This bound was added in 2.4.1 specifically to address that complexity ([CHANGELOG](https://github.com/hukkin/tomli/blob/18d8d59db6d632ebbcfe63f1f7636145d652da21/CHANGELOG.md#L8-L11)).

> **For the owner:** The key-length cap is read from `sys.getrecursionlimit()` once at import, so it is process-wide and whatever your application set it to; raising that limit also raises Tomli's tolerance for quadratic key handling. Note also that exceeding it raises `RecursionError`, not `TOMLDecodeError` — if you catch only `TOMLDecodeError` around `loads`, a pathological key will escape your handler.

The string leaves this stretch with its name read and its cursor parked on the first of the two closing brackets. Nothing has been written to the output dict yet, and nothing has been forbidden. `create_list_rule` is about to ask the `Flags` object whether this namespace may be claimed at all.

> **Leaves as:** `(10, ('players',))` — a cursor at index 10 (on `]`) and the key tuple `('players',)`, returned into `create_list_rule`
