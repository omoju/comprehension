# Chapter 1 · The Trust Boundary, and the Unguarded Door Beside It

> **Enters as:** `s = '<script>alert(document.cookie);</script>'` — a plain `str` of unknown provenance

The world this string is about to enter is small and already assembled. At import time the package picked one of two engines for the actual character replacement: it tries the compiled `_speedups._escape_inner` and falls back to the pure-Python `_native._escape_inner` if the C extension was never built ([`__init__.py#L7-L10`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L7-L10)). Whichever one it got, the behaviour is the same; only the speed differs. Nothing else is configured. There is no policy object, no allowlist, no sanitizer. There is a function and a type.

The string itself is forty characters of someone else's intent: `<script>alert(document.cookie);</script>`. Dropped verbatim into a page, it stops being text and starts being code. It is handed to `escape`.

## The first door: `type(s) is str`

`escape` begins with a single identity check ([`__init__.py#L39-L40`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L39-L40)). Not `isinstance` — `type(s) is str`, exactly. Our comment is exactly a `str`, so it takes this path immediately and never reaches the two branches below it.

The comment above that line explains the choice, and it is a security choice, not a micro-optimisation: a proxy object can report a borrowed `__class__`, so `isinstance(s, str)` can be made to return `True` for something that is not a string at all ([`__init__.py#L35-L38`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L35-L38)). `type()` cannot be lied to the same way, so a proxy falls through to the slower, more careful branches instead of being waved past. The repository pins this behaviour with a deliberately deceitful `Proxy` class ([`tests/test_escape.py#L50-L55`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/tests/test_escape.py#L50-L55)).

## The replacement itself: exactly five characters

Inside, `_escape_inner` does the only transformation this library performs. In the Python implementation it is five chained `str.replace` calls ([`_native.py#L1-L8`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/_native.py#L1-L8)): `&` → `&amp;`, then `>`, `<`, `'`, `"`. The order is load-bearing — `&` is replaced *first*, because the other four replacements all introduce new `&` characters; reverse the order and every entity would be escaped twice. The C version does the same five, in one pass, sized ahead of time, with a shortcut: if the scan finds nothing to escape it increments the refcount and hands back the *same* string object ([`_speedups.c#L84-L87`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/_speedups.c#L84-L87), dispatched by width at [`#L151-L171`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/_speedups.c#L151-L171)).

Our comment has four angle brackets and nothing else of interest, so it comes back three characters longer per bracket: `'&lt;script&gt;alert(document.cookie);&lt;/script&gt;'`. The parentheses, the dot, the semicolons, the word `alert` — all untouched. They were never dangerous as *text*; what made the string dangerous was the brackets that let it leave text and become a tag.

> **For the owner:** Five characters is the entire scope of the escaping: `& > < ' "`. Backtick, `=`, and whitespace are not touched. That is sufficient for HTML text nodes and for *quoted* attribute values — the quote characters are escaped, so the value cannot break out. It is **not** sufficient for an unquoted attribute (`<a href=%s>`), for a URL scheme (`href="javascript:..."` survives escaping untouched), or for anything inside `<script>` or `<style>`, where HTML entity rules do not apply. If your templates have any of those shapes, MarkupSafe is not what protects them.

## The second door, which is not locked at all

The escaped text is handed to `Markup(...)` ([`__init__.py#L40`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L39-L40)), and the trace records the constructor receiving `object='&lt;script&gt;alert(document.cookie);&lt;/script&gt;', encoding=None, errors='strict'`.

`Markup.__new__` performs no escaping whatsoever ([`__init__.py#L122-L131`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L122-L131)). It checks whether the object has an `__html__` method and, if so, uses its return value; then — since `encoding` is `None` here — it calls `str.__new__` and returns. The bytes-decoding road, where `encoding` and `errors` are forwarded, is not taken on this run or on any other in this scenario.

So the value that leaves is the same characters, in a different type: `Markup('&lt;script&gt;alert(document.cookie);&lt;/script&gt;')`. The class carries `__slots__ = ()` ([`__init__.py#L120`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L120)) — there is no flag, no field, no provenance record. The type *is* the claim. When the scenario prints it, `__repr__` wraps `str.__repr__` in the class name ([`__init__.py#L167-L168`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L167-L168)) and yields `"Markup('&lt;script&gt;alert(document.cookie);&lt;/script&gt;')"`, so in a log or a REPL you can tell safe text from a bare string at a glance.

> **For the owner:** This is the asymmetry to understand before signing off. `escape()` **produces** safety; `Markup()` merely **asserts** it, on any string at all, with no check. `Markup(request.args["q"])` is a cross-site scripting hole, and the library will not notice. The same applies to a user-defined `__html__`, whose output `__new__` takes on faith at [L125-L126](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L125-L126). In review, every `Markup(` call site is a trust assertion by a human; grep for them, and expect the argument to be a literal.

## The round trip: escaping what is already safe

The scenario immediately rebuilds the expected value with `Markup('&lt;script&gt;...')` for its assertion (the constructor call at trace line 8, which takes the same no-op path), and then does the thing a real template does constantly: it escapes something that has already been escaped.

This time `escape` takes a different road. `Markup` is a subclass of `str`, so `type(s) is str` is `False` and the fast path is refused — precisely the conservatism from the proxy decision, here paying off differently. The next check, `hasattr(s, "__html__")`, succeeds ([`__init__.py#L42-L43`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L42-L43)), and `Markup.__html__` simply returns `self` ([`__init__.py#L133-L134`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L133-L134)). The five replacements never run. `&lt;` does not become `&amp;lt;`. Escaping is idempotent, which is the property that lets safe fragments nest inside safe fragments later in this story.

The trace shows `__html__` called twice on this one round trip — lines 11-12 from `escape`, then lines 14-15 from inside `Markup.__new__`, which re-checks for `__html__` on the value it was handed. For a `Markup` the returned value *is* `self`, so the same method runs again and returns the same object; it costs nothing. The thing to carry forward is the shape of it: the *result* of `__html__` is inspected for `__html__` again. An object's own `__html__` is called once by `escape`; if it returns a `Markup`, that `Markup`'s trivial `__html__` runs a second time.

The road not taken here, for completeness: a `str` *subclass* without `__html__` — the repository's `ReferenceStr` is the test case ([`tests/test_escape.py#L58-L68`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/tests/test_escape.py#L58-L68)) — would fall to the third branch, `Markup(_escape_inner(str(s)))` ([`__init__.py#L45`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L45)). That same branch is why `escape(None)` is `Markup('None')` rather than empty, and why `escape_silent` exists as the opt-in for optional values ([`__init__.py#L48-L61`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L48-L61)).

The comment is now inert text wearing a type that says so. It is ready to be put into a page.

> **Leaves as:** `Markup('&lt;script&gt;alert(document.cookie);&lt;/script&gt;')` — and the same value, unchanged and unescaped a second time, after a round trip back through `escape`
