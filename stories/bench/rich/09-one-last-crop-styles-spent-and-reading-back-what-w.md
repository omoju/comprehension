# Chapter 9 · One Last Crop, Styles Spent, and Reading Back What Was Printed

> **Enters as:** a stream of `Segment`s beginning `Segment('┏━━━━━━━━━━━━━━┳…┓', Style())`, `Segment('\n')`, `Segment('┃', Style())`, `Segment(' ', Style(magenta, bold))`, `Segment('Date        ', Style(magenta, bold))`, … and ending with the bottom border

The generator is drained into a list — eighty-odd segments, the whole table — and `print` now has one thing left to do before it lets go of them.

## The measure that is actually enforced

`crop` defaulted to `True`, so every segment goes through `Segment.split_and_crop_lines` at `self.width` with `pad=False` ([`console.py#L1749-L1756`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1749-L1756)). The trace shows `Console.width` resolved again to `100` — `self._width` wins over anything the OS reports ([`console.py#L1040-L1043`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1040-L1043)) — and then the splitter walking the stream, cutting at each `\n` and handing each accumulated line to `adjust_line_length` ([`segment.py#L333-L351`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/segment.py#L333-L351)).

The first line is the top border alone. `adjust_line_length` sums `segment.cell_length` ([`segment.py#L372`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/segment.py#L372)), which for a non-control segment is `cell_len(text)` ([`segment.py#L78-L86`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/segment.py#L78-L86)), and `cell_len` — short string, so the cached path — returns **89** ([`cells.py#L98-L110`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/cells.py#L98-L110)). Each heavy box-drawing glyph is one cell, so the 89-character border is 89 cells wide, exactly the `table_width` computed in Chapter 7. 89 is less than 100 and `pad=False`, so the branch taken is the one that copies the line unchanged ([`segment.py#L375-L379`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/segment.py#L375-L379)) — no truncation, and no padding out to the console width either, which is why the exported text has no trailing spaces. The newline segment is re-appended and the line goes into `self._buffer` ([`segment.py#L341-L346`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/segment.py#L341-L346)). Seven more lines follow the same route.

Had any line been longer, the `line_length > length` branch would have rebuilt it segment by segment and cut the last one with `set_cell_size` ([`segment.py#L380-L393`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/segment.py#L380-L393)) — which, for a split double-width glyph, substitutes spaces rather than half a character.

> **For the owner:** This crop is the only unconditional width guarantee in the pipeline; `max_width` in `ConsoleOptions` is advice that a renderable may ignore, but `print(crop=True)` truncates whatever it is handed. Note the escape hatch cuts the other way: `soft_wrap=True` sets `crop = False` ([`console.py#L1697-L1702`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1697-L1702)), so a custom `__rich_console__` that ignores the width can then emit lines wider than the console. Review any use of `soft_wrap` alongside third-party renderables.

## Leaving the buffer context

`print`'s `with self:` block ends, `__exit__` calls `_exit_buffer` ([`console.py#L862-L864`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L862-L864)), the depth counter goes from 1 back to 0, and `_check_buffer` runs ([`console.py#L817-L820`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L817-L820)). That counter is the reason a table is one write and not eighty: nested prints only increment it, and nothing reaches the file until the outermost context exits.

`_check_buffer` has two outcomes worth knowing ([`console.py#L2044-L2057`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2044-L2057)): if `quiet` is set the buffer is discarded wholesale and nothing is written, and a `BrokenPipeError` from the write is routed to `on_broken_pipe`, whose default is to go quiet, point stdout at `/dev/null` and raise `SystemExit(1)` ([`console.py#L2030-L2042`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2030-L2042)). Neither is a silent corruption; both are deliberate.

Inside `_write_buffer`, under the console lock, the recording happens *first* — `record` is true and `_buffer_index` is 0, so a copy of the buffer is appended to `self._record_buffer` under its own separate lock ([`console.py#L2062-L2065`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2062-L2065)). What is recorded is exactly what is about to be written, once per flush.

> **For the owner:** `record=True` makes `_record_buffer` grow without bound; nothing trims it, and only an `export_*` call with `clear=True` empties it. A long-running process that records and never exports leaks every segment it ever printed. Treat `record` as a debugging or one-shot-export setting, not a default.

## Styles, spent

`_render_buffer` walks the copy once ([`console.py#L2132-L2154`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2132-L2154)). It reads `not_terminal = not self.is_terminal` up front — `False` here, as it has been all run — and would strip colour entirely if `no_color` were set ([`console.py#L2139-L2140`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2139-L2140)). Then, per segment: truthy style → `style.render(text, …)`; otherwise append the text, unless it is a control code and the target is not a terminal, in which case it is dropped ([`console.py#L2141-L2151`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2141-L2151)).

The trace shows the triage plainly. `Style.__bool__` returns `False` for the border segments ([`style.py#L340-L342`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/style.py#L340-L342)) and their text is appended raw. It returns `True` for `'Date        '`, `'Title                            '`, `'Production Budget'`, `'    Box Office'`, `'Dec 20, 2019'`, `'Solo'`, `'$1,332,539,889'` — and each of those goes to `Style.render`, which is handed `color_system=None` and returns the string **unchanged** ([`style.py#L710-L711`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/style.py#L710-L711)).

That is the end of the thread begun in Chapter 1. The magenta, the bold, the dim, the `[red]` on *Solo* and the `[bold]` on `$1,332,539,889` all travelled the full length of the pipeline as real `Style` objects attached to real `Segment`s, composed correctly at every join — and then evaporated at the last instruction, because the colour system was decided once, at construction, from a `stdout` that was not a terminal. Flip that one input and exactly the same segments emit SGR sequences.

The joined string — `'┏━━━…┓\n…└───…┘\n'` — is written in a single `self.file.write`, followed by `flush()`, and the buffer is deleted ([`console.py#L2121-L2130`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2121-L2130)). On Windows the same text would be split into ~8K-character batches to dodge a CPython write-size bug ([`console.py#L2098-L2117`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2098-L2117)), and a `UnicodeEncodeError` on either path is re-raised with a `PYTHONIOENCODING` hint attached ([`console.py#L2125-L2127`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2125-L2127)).

## Reading it back

`console.export_text()` opens the record buffer — the accumulated copy of all three prints ([`console.py#L2192-L2222`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2192-L2222)). With the default `styles=False` it joins `segment.text` for every non-control segment ([`console.py#L2214-L2219`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2214-L2219)), which in this run is byte-for-byte what went to stdout, and returns `'Hello World!\nWhere there is a Will t…┴────────────────┘\n'`. Then, because `clear` defaults to `True`, it empties the buffer ([`console.py#L2220-L2221`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2220-L2221)).

The scenario's five assertions hold against that string, including `"Solo: A Star Wars Story"` — the tags are gone because they became spans in Chapter 8, and the spans produced no codes here.

> **For the owner:** Two things about export. The `record=True` precondition is an `assert` ([`console.py#L2204-L2206`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2204-L2206)), so under `python -O` it vanishes and a forgotten flag yields an empty string instead of an error. And `export_text`, `export_html` and `export_svg` share one buffer and all clear it by default — calling two of them in a row gives the second one nothing. Pass `clear=False` if you need more than one format from the same run.

> **Leaves as:** `'┏━━━…┓\n…└──────────────┴───────────────────────────────────┴───────────────────┴────────────────┘\n'` written to stdout and flushed, `self._buffer` empty, and `export_text()` returning `'Hello World!\nWhere there is a Will there is a way.\n┏━━━…┘\n'` with the record buffer drained
