# Chapter 2 · Two Strings Become One Text

> **Enters as:** `objects=('Hello', 'World!')`, `sep=' '`, `end='\n'`, `style='bold red'`, every other print argument `None`

The call lands in `Console.print` ([`console.py#L1652-L1669`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1652-L1669)). Before the two strings are looked at, two guards run past them. `objects` is non-empty, so the "print nothing" substitution of a `NewLine()` is skipped ([`L1689-L1693`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1689-L1693)); `soft_wrap` is `None` and falls back to the console's `False`, so no-wrap and overflow stay unset and `crop` stays `True` ([`L1695-L1702`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1695-L1702)). That last decision is a promise cashed in much later: because `crop` is still `True`, every line this print produces will be measured and truncated against the console width before it reaches the file.

Then `with self:` ([`L1704`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1704)) enters the buffer context — `__enter__` calls `_enter_buffer`, which bumps the thread-local `_buffer_index` from `0` to `1` ([`L857-L860`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L857-L860), [`L813-L815`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L813-L815)). Nothing will be written until that index comes back to zero. The strings are now inside a transaction.

## Being admitted

`_collect_renderables` takes the tuple and walks it ([`L1500-L1587`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1500-L1587)). Before the loop it chooses a highlighter: `highlight` is `None` and the console's `_highlight` is `True`, so `_highlighter` becomes the console's `ReprHighlighter` rather than the no-op `NullHighlighter` ([`L1546-L1548`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1546-L1548)).

`'Hello'` is first put through `rich_cast` ([`protocol.py#L18-L41`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/protocol.py#L18-L41)), which repeatedly calls `__rich__` on anything that has one. A plain `str` has none, so it comes straight back as `'Hello'`. The loop is worth knowing in outline, because it is where Rich decides what kind of thing you handed it: a `str` is rendered to `Text`, an existing `Text` is taken as-is, anything satisfying the `ConsoleRenderable` protocol is appended untouched, anything "expandable" (list, dict, dataclass…) is wrapped in `Pretty`, and everything else is stringified through the highlighter ([`L1556-L1579`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1556-L1579)). Our strings take the first branch.

## Becoming Text

`render_str` is where the three content defaults are resolved ([`L1437-L1439`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1437-L1439)): `emoji`, `markup` and `highlight` are all `None` on this call, so all three take the console's value — all `True`.

Markup being enabled sends `'Hello'` into `markup.render` ([`L1441-L1449`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1441-L1449)). The first thing that function does is check for a `[`; there isn't one, so it takes the fast path — emoji substitution and a plain `Text`, with the tag parser never entered ([`markup.py#L127-L132`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/markup.py#L127-L132)).

`_emoji_replace` runs the regex `(:(\S*?)(?:(?:\-)(emoji|text))?:)` over the text and looks each name up in the `EMOJI` table ([`_emoji_replace.py#L9-L31`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/_emoji_replace.py#L9-L31)). `'Hello'` has no colons, so it returns `'Hello'` unchanged. The important detail for an unknown code is the `except KeyError: return emoji_code` at [`L28-L29`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/_emoji_replace.py#L28-L29): a name Rich doesn't recognise is put back verbatim rather than raising.

Then `Text.__init__` ([`text.py#L144-L165`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/text.py#L144-L165)) does the one thing that happens to *every* string printed through Rich: `strip_control_codes` ([`L156`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/text.py#L156)). That is a `str.translate` with a table mapping bell, backspace, vertical tab, form feed and carriage return to `None` ([`control.py#L181-L192`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/control.py#L181-L192), table at [`L9-L18`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/control.py#L9-L18)). `'Hello'` survives intact, and the trace records the result: `<text 'Hello' [] ''>` — plain text, no spans, no style.

> **For the owner:** Rich deletes five control characters from every string it renders, silently and without a flag to turn it off. Treat `\r`, `\b`, `\a`, `\v` and `\f` as unprintable through this API, and do not use Rich's `print` for carriage-return-based progress tricks or for any text whose byte-for-byte fidelity matters. Note that ESC (`0x1b`) is *not* in that list — raw ANSI sequences pass through; use `Text.from_ansi` if you need them decoded rather than emitted.

## Being highlighted anyway

Highlighting is on, so the freshly-made `Text` does not go straight back. `render_str` stringifies it and hands it to the `ReprHighlighter` ([`L1462-L1466`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1462-L1466)). `Highlighter.__call__` builds a *second* `Text` from the string — another `strip_control_codes` pass — and calls `highlight` on it ([`highlighter.py#L32-L39`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/highlighter.py#L32-L39)). `RegexHighlighter.highlight` then runs `highlight_regex` once per pattern in `highlights` ([`L75-L77`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/highlighter.py#L75-L77)); `ReprHighlighter` has four of them — tags, `name=value` pairs, braces, and one big combined alternation covering numbers, paths, URLs, UUIDs, IP addresses, quoted strings, `True`/`False`/`None` and more ([`L84-L103`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/highlighter.py#L84-L103)). Each named regex group becomes a `Span` prefixed with `repr.` ([`text.py#L618-L630`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/text.py#L618-L630)).

The trace shows the first pass returning `0` and three more passes behind it. `'Hello'` matches nothing, so the highlighted copy is still `<text 'Hello' [] ''>`. `copy_styles` merges the (empty) span list from the markup-rendered original back onto it ([`text.py#L1054-L1060`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/text.py#L1054-L1060)), and the highlighted copy is what `render_str` returns.

`'World!'` takes exactly the same road and arrives as `<text 'World!' [] ''>`.

> **For the owner:** Markup, emoji and automatic highlighting are all on by default and all apply to whatever string you pass, including data you did not write. A `:name:` sequence becomes an emoji, a number or a `/path` or a `"quoted string"` acquires a style you never asked for, and square brackets are parsed as tags (which can raise — see Chapter 5). Pass `markup=False, emoji=False, highlight=False` per call, or set them on the `Console`, whenever you print untrusted or machine-readable content. `Console.out` already does exactly that ([`console.py#L1639-L1650`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1639-L1650)).

## Becoming one

Both `Text` objects were accumulated in a local list, not appended to the result yet. `check_text` closes them out ([`L1550-L1554`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1550-L1554)): it builds a separator `Text(' ', justify=None, end='\n')` and calls `sep_text.join([...])`.

`Text.join` ([`text.py#L778-L815`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/text.py#L778-L815)) starts from a `blank_copy` of the separator — so the result inherits the separator's `style`, `justify`, `overflow`, `no_wrap`, `end` and `tab_size`, which is how `end='\n'` makes it onto the joined text. Its inner `iter_text` generator interleaves the pieces with the separator using `loop_last` ([`_loop.py#L18-L28`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/_loop.py#L18-L28)), and the trace shows the alternation plainly: `'Hello'` (length 5), `' '` (length 1), `'World!'` (length 6), then `None` to stop.

The accounting in that loop is the part that matters. For each piece, `join` extends the text fragments, re-emits the piece's own `style` as a span over `[offset, offset + len)`, and shifts every one of the piece's existing spans by `offset` ([`L805-L814`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/text.py#L805-L814)). Styles survive concatenation because their offsets are rewritten, not because the strings happen to be short. Here there are no styles to carry, so `_spans` stays empty and `_length` ends at `0 + 5 + 1 + 6 = 12`.

The two strings the caller typed are now one object: `<text 'Hello World!' [] ''>`, returned as a single-element list ([`L1581-L1587`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1581-L1587) — `self.style` is `None` on this console, so the `Styled` wrapping step is skipped). Nothing has been measured, wrapped or written. That starts next.

> **Leaves as:** `[<text 'Hello World!' [] ''>]` — one `Text`, plain `'Hello World!'`, `len` 12, `spans == []`, `style == ''`, `end == '\n'`
