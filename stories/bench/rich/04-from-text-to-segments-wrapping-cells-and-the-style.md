# Chapter 4 · From Text to Segments: Wrapping, Cells, and the Style Stack

> **Enters as:** `<text 'Hello World!' [] ''>`, to be rendered under `ConsoleOptions(max_width=100)` with `render_style=Style(color=Color('red', ColorType.STANDARD, number=1), bold=True)`

Because `style` was given, `print` takes the lower of its two branches ([`console.py#L1729-L1741`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1729-L1741)). First it makes a spare newline to hand out later — `Segment.line()` ([`segment.py#L181-L184`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/segment.py#L181-L184)) returns `Segment('\n')` — and then it opens the pipeline that the `Text` will travel down: `Segment.split_lines_terminator(render(renderable, render_options))`.

Nothing has actually happened yet. `Console.render` is a generator; so is `split_lines_terminator`. The whole chapter is driven by the `for` loop pulling items out of the far end.

## The gate

The first pull enters `Console.render` ([`console.py#L1294-L1343`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1294-L1343)). Two checks guard the door. The width guard at [`L1311-L1314`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1311-L1314) returns an empty render when `max_width < 1` — the comment says why: it prevents recursion errors when a container keeps subdividing an already-zero-width space. With `max_width=100` the `Text` walks straight past it.

Then `rich_cast` runs again ([`L1317`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1317)) — the trace shows it handing the `Text` back unchanged — and the object is sorted into one of exactly three kinds: something with `__rich_console__`, a bare `str`, or an error ([`L1318-L1329`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1318-L1329)). `Text` has the method, so its own render method is asked for an iterable.

> **For the owner:** `Console.render` is the only entry point for arbitrary objects, and it rejects anything it cannot handle with `errors.NotRenderableError` naming the object ([`console.py#L1325-L1329`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1325-L1329)). Note that this raises from inside `print`, lazily, as the generator is consumed — so a bad object reaches you as an exception at output time, not when it was constructed. If you print values of uncertain type, catch `rich.errors.NotRenderableError` at the call site or convert with `str()` first.

Before the loop that drains the result, `render` calls `_options.reset_height()` ([`L1338`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1337-L1343)) — another copy, this one clearing `height` so a fixed height set for a parent is not silently inherited by its children.

## Measuring in cells, not characters

`Text.__rich_console__` ([`text.py#L689-L705`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/text.py#L689-L705)) resolves the three layered defaults — `justify` falls through `self.justify` and `options.justify` to `'default'`, `overflow` to `'fold'` — and asks `pick_bool(self.no_wrap, options.no_wrap, False)` ([`_pick.py#L4-L17`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/_pick.py#L4-L17)) whether wrapping is off. Both candidates are `None`, so it returns the literal `False`: wrap.

`Text.wrap` ([`text.py#L1201-L1250`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/text.py#L1201-L1250)) splits on newlines first ([`L1230`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/text.py#L1230)); `'Hello World!'` has none, so `split` takes its early return and hands back `Lines([<text 'Hello World!'>])` built from a copy ([`L1082-L1083`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/text.py#L1082-L1083)). No tab is present, so `expand_tabs` is skipped, and the single line goes to `divide_line(str(line), 100, fold=True)` ([`L1239`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/text.py#L1239)).

This is where the width promise becomes arithmetic ([`_wrap.py#L26-L78`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/_wrap.py#L26-L78)). The `words` generator ([`L12-L23`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/_wrap.py#L12-L23)) yields `(0, 6, 'Hello ')` — a word plus its trailing whitespace. The loop measures the word twice: `cell_len(word.rstrip())` is 5, which is what must fit, and `cell_len(word)` is 6, which is what the cursor advances by ([`L45-L50`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/_wrap.py#L44-L50)). Trailing spaces are allowed to run off the end of a line; visible characters are not. Then `(6, 12, 'World!')`, length 6 against 94 remaining. Both fit, and the trace records the return: `[]` — no break positions.

The unit is a *terminal cell*, not a Python character. `cell_len` ([`cells.py#L98-L110`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/cells.py#L98-L110)) routes strings under 512 characters through an LRU cache of 4096 entries and falls through to `_cell_len`, which has a fast path: if every character is in the frozen set of known single-cell ranges, the answer is just `len(text)` ([`L124-L125`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/cells.py#L124-L125)). ASCII takes that path. Anything else is looked up in a per-Unicode-version width table by binary search ([`L46-L78`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/cells.py#L46-L78)), so a CJK glyph counts as two and a zero-width joiner sequence counts once. This is the reason Rich's columns line up with text that `len()` would get wrong.

The road not taken is one branch down: had a word been wider than the whole line, `fold=True` would have sent it to `chop_cells` and broken it mid-word across several lines ([`_wrap.py#L54-L66`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/_wrap.py#L54-L66)); with `fold=False` it would have been cropped instead.

With no offsets, `Text.divide([])` returns a single-line `Lines` from another copy ([`text.py#L1117-L1118`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/text.py#L1117-L1118)). `rstrip_end(100)` sees a length of 12 and does nothing ([`L666-L678`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/text.py#L666-L678)). `Lines.justify` is called with `justify='default'`, which matches none of its four branches — left, center, right, full ([`containers.py#L129-L167`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/containers.py#L129-L167)) — and returns having touched nothing. `truncate(100, overflow='fold')` measures 12 cells against 100 and leaves the text alone ([`text.py#L873-L884`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/text.py#L873-L884)). The `Text` comes out of `wrap` exactly as it went in, having been copied three times on the way.

## Spans into segments

Back in `__rich_console__`, the lines are rejoined with `Text("\n").join(lines)` ([`text.py#L704`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/text.py#L704)) — the same offset-shifting join from Chapter 2, here with one element and so no separator inserted — and the result is handed to `Text.render(console, end=self.end)` with `end='\n'`.

`Text.render` ([`text.py#L719-L776`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/text.py#L719-L776)) checks `self._spans` first. There are none, so it takes the four-line fast path: one `Segment` for the text, one for the end character, return ([`L731-L735`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/text.py#L731-L735)). The trace shows the first of those surfacing all the way up through `Console.render` as `Segment('Hello World!')`.

The machinery below that fast path is the style stack the chapter is named for, and the markup string and the table cells will both use it. It builds a list of `(offset, leaving, style_id)` events — one for each span start, one for each span end — sorts them, and walks the text between consecutive offsets while pushing and popping ids on a stack ([`L738-L774`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/text.py#L738-L774)). At each step the active styles are combined, with the result cached by the tuple of ids. Overlapping spans therefore *compose* rather than overwrite: `[bold][red]…[/red][/bold]` yields one segment carrying both, not two fighting segments.

## Line endings, and the style arriving last

`split_lines_terminator` ([`segment.py#L275-L304`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/segment.py#L275-L304)) accumulates the first segment, then receives `Segment('\n')`, splits on the newline, and yields what the trace records at line 300: `([Segment('Hello World!')], True)`. The newline has been converted from a character into a flag. Control segments are deliberately excluded from this splitting (`and not segment.control` at [`L291`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/segment.py#L291)), so an escape sequence that happens to contain a newline byte cannot be chopped in half.

Now the style finally meets the text. `Segment.apply_style(line, render_style)` ([`segment.py#L186-L225`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/segment.py#L186-L225)) checks the style is truthy and returns a *generator expression* — trace line 304 shows exactly that object — which `extend` then drains, which is why `Style.__add__` only appears at trace line 305. For each segment it computes `style + segment.style` ([`L208-L211`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/segment.py#L208-L211)), and crucially passes `None` as the style for control segments so cursor codes are never wrapped in SGR sequences.

The segment's own style is `None` here, so `Style._add` returns `self` immediately ([`style.py#L733-L735`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/style.py#L732-L735)); `__add__` then checks for a link, finds none, and hands back the same cached red-bold object ([`L757-L759`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/style.py#L757-L759)). The `Style.__hash__` call at trace line 306 is the `lru_cache` key being computed for `_add`.

> **For the owner:** Note the direction of that addition: `apply_style` composes as *base + segment*, so the `style=` argument to `print` sits **underneath** whatever styles the renderable already carried. In `Style._add` the right-hand side's set attributes win ([`style.py#L743-L748`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/style.py#L743-L748)). A per-call `style="bold red"` is therefore a floor, not an override — markup spans and table cell styles will beat it on any attribute they both set. Do not rely on `style=` to force a colour onto content you do not control.

The `for` loop appends the spare `Segment('\n')` because `add_new_line` was `True`, then asks for a second line. Both generators resume where they stopped — the trace shows those resumptions at lines 313–320 as calls returning `None` — find nothing left, and finish. `Console.render` is lazy and single-use; what you get back is a stream, consumed once.

`new_segments` now holds two items, which is where Chapter 5 picks them up.

> **Leaves as:** `new_segments == [Segment('Hello World!', Style(color=Color('red', ColorType.STANDARD, number=1), bold=True)), Segment('\n')]`
