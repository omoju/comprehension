# Chapter 3 · The Innermost Escape: the user's name

> **Enters as:** `Markup('<span class="user">{0}</span>')` and the single argument `'Alice "The <b>Great</b>"'`, inside `User.__html__`

The name starts its own render. `Markup.format` runs again, one level down, on the span template ([`__init__.py:313-315`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L313-L315)). It builds a second `EscapeFormatter` and passes `Markup.escape` to it ([`__init__.py:335-337`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L335-L337)). This formatter is new and shares nothing with the outer one. `string.Formatter.vformat` parses the template, finds the field `{0}`, and calls `format_field` with `value='Alice "The <b>Great</b>"'` and `format_spec=''`.

The name is a plain `str`. It has no `__html_format__` and no `__html__`, so the first two tests in `format_field` fail ([`__init__.py:340-342`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L340-L342)). The data falls to the third branch, the default road ([`__init__.py:350-353`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L350-L353)). There `format_field` calls `super().format_field(value, str(format_spec))`, which is Python's own format machinery. The call to `str()` on the specifier is deliberate: a `Markup` specifier would otherwise invoke the wrong `__format__` callbacks. With an empty specifier the name comes back unchanged.

Then the escape happens, on the rendered text, not on the original object ([`__init__.py:354`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L354)). `Markup.escape` calls the module-level `escape` ([`__init__.py:235`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L235)). The value is an exact `str`, so `escape` takes the fast path of chapter 1 ([`__init__.py:39-40`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L39-L40)). `_escape_inner` replaced the quotes with `&#34;` and the angle brackets with `&lt;` and `&gt;` ([`_native.py:1-8`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/_native.py#L1-L8)). `Markup.__new__` wrapped the result, and the trace shows `Markup('Alice &#34;The &lt;b&gt;Great&lt;/b&gt;&#34;')`. The class of that value already equals `cls`, so `Markup.escape` returned it without a new object ([`__init__.py:237-240`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L237-L240)).

> **For the owner:** Note why the double quote matters here. The name lands between the quotes of `class="user"`-style markup, and `&#34;` keeps it inside its attribute. `_escape_inner` replaces 5 characters only. It does not touch `=`, the backtick, or whitespace. An unquoted attribute value is therefore not protected by this library. Require quotes around every attribute in your templates.

`format_field` then strips the safe type on purpose. It returns `str(self.escape(rv))`, and the trace records the plain string `'Alice &#34;The &lt;b&gt;Great&lt;/b&gt;&#34;'`, without the `Markup` wrapper. The reason is mechanical: `string.Formatter.vformat` joins fields with plain string operations and knows nothing about `Markup`. The escaped characters survive the join; the type does not.

> **For the owner:** The guarantee is absent for 1 step here, and `Markup.format` restores it at the final wrap ([`__init__.py:315`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L315)). `EscapeFormatter` is a public name in the module. If your code calls `EscapeFormatter.vformat` directly, it receives a plain `str` and must wrap the result itself.

`Markup.format` wrapped the joined text with `self.__class__(...)`. `Markup.__new__` received `'<span class="user">Alice &#34;The &lt;b&gt;Great&lt;/b&gt;&#34;</span>'` and returned it as `Markup` ([`__init__.py:122-131`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L122-L131)). The span tags are live markup; the name inside them is inert text. `User.__html__` returned that value to `User.__html_format__`.

The anchor template now renders, with the same machinery twice more. The trace collapses it into one line, `Markup.format ×1 more`. The first field is the integer `3`, which has neither method, so it takes the default branch and escapes to itself. The second field is the span, and `Markup` defines `__html_format__` ([`__init__.py:325-329`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L325-L329)). The specifier is empty, so that method returns `self`, and the span text enters the anchor without a second escape. The completed fragment left `User.__html_format__` as a `Markup`.

> **Leaves as:** `Markup('<a href="/user/3"><span class="user">Alice &#34;The &lt;b&gt;Great&lt;/b&gt;&#34;</span></a>')`, on its way back to the outer `format_field`
