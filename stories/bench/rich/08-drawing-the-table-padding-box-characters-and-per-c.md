# Chapter 8 · Drawing the Table: Padding, Box Characters, and Per-Cell Styles

> **Enters as:** `widths = [14, 35, 19, 16]` and `ConsoleOptions(max_width=89, highlight=False, height=None)`, with the cells still raw strings on `Column._cells`

Four numbers and twelve strings. `_render` now has to turn them into a stream of `Segment`s — frame, padding, styled text — in the exact order a terminal would read them.

## Dressing the frame

The first thing `_render` resolves is style, before geometry ([`table.py#L755-L760`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L755-L760)). `self.style` is the string `'none'`, so `console.get_style('none')` is asked twice — once for the table, once for `self.border_style or ""` — and the trace shows it returning `Style()` both times, the null style that `Style.parse` short-circuits to for an empty or `"none"` definition ([`style.py#L510-L511`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/style.py#L510-L511)). Adding them gives `Style()` again: `Style.__add__` delegates to the cached `_add`, which returns `self` unchanged when the right-hand style is null ([`style.py#L732-L737`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/style.py#L732-L737)). So every box character in this run will carry an empty style — the `Segment('┏━━…┓', Style())` the trace ends on.

## Columns become rows

`_render` builds a generator per column and then transposes them ([`table.py#L761-L766`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L761-L766)). Each `_get_cells` call yields the header, then every body cell, then the footer if one is shown ([`table.py#L667-L682`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L667-L682)); `zip(*…)` pulls one from each in lockstep, which is why the trace shows `_get_cells` entered once and then resumed sixteen more times — four columns × four rows.

For the Date column the trace spells out what each cell gets. The header style is `get_style(self.header_style or "") + get_style(column.header_style)`, i.e. `Style(color=magenta, bold=True)` plus the empty per-column override ([`L670-L674`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L670-L674)). The body cells get `cell_style = get_style(column.style or "")` — `Style(dim=True)`, the `style="dim"` passed to `add_column` back in Chapter 6 ([`L675-L677`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L675-L677)). Note the asymmetry: the header's style replaces the column's, it does not stack on top of it.

Then padding. `any(padding)` is true for `(0, 1, 0, 1)`, so each raw cell is wrapped in a `Padding` renderable ([`L684-L691`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L684-L691)). `loop_first_last` tells `get_padding` whether this is the first or last row, and with `pad_edge=True` and `collapse_padding=False` nothing is trimmed: the trace shows `get_padding(first_row=True, last_row=False) → (0, 1, 0, 1)`, cached against that flag pair ([`L642-L665`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L642-L665)). Out comes `_Cell(style=Style(magenta, bold), renderable=Padding('Date', (0,1,0,1)), vertical='top')` — the vertical taken from the renderable if it declares one, else from the column ([`L686-L691`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L686-L691)).

The string `'Dec 20, 2019'` is still a string at this point. So is `'[red]Solo[/red]: A Star Wars Story'`.

## Choosing the characters

Before a border is drawn, the box is given a chance to change itself ([`table.py#L767-L774`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L767-L774)). `pick_bool(self.safe_box, console.safe_box)` picks the first non-`None` of the table's `None` and the console's `True`, returning `True` ([`_pick.py#L4-L17`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/_pick.py#L4-L17)), and `Box.substitute` runs two tests ([`box.py#L67-L83`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/box.py#L67-L83)): legacy Windows, which would swap `HEAVY_HEAD` for `SQUARE` from the substitution table ([`box.py#L405-L412`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/box.py#L405-L412)), and `options.ascii_only`, which would replace it with plain `+-|` ASCII. The trace shows `ascii_only → False` — the console's encoding is `'utf-8'` ([`console.py#L142-L145`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L142-L145)) — so `HEAVY_HEAD` survives intact. (`get_plain_headed_box`, which strips the header-specific characters, is skipped because `show_header` is true.)

> **For the owner:** The box characters are chosen from `options.encoding`, which is read off the output file object, not from a setting. Redirect the same program into a `cp1252` pipe and the table silently renders in ASCII instead of raising — that is the intended degradation, but confirm it is acceptable for any consumer that parses your output, and pin `box=box.ASCII` explicitly if it must never vary.

## The first line

`Box.get_top` walks the widths with `loop_last`, emitting a corner, a run of `━` per column, and a divider between each ([`box.py#L95-L113`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/box.py#L95-L113)). The result is `'┏' + '━'×14 + '┳' + '━'×35 + '┳' + '━'×19 + '┳' + '━'×16 + '┓'` — 89 characters, exactly the `table_width` computed in Chapter 7. It is yielded as `Segment('┏━━━…┓', Style())` followed by `Segment('\n')`, and those two are the first things this renderable has produced ([`table.py#L804-L806`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L804-L806)).

## Each row, one cell at a time

From here the loop runs per row ([`table.py#L813-L931`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L813-L931)) — the eighty further pumps of the generator the trace folds away. For the header row `row_style` is `Style.null()`; body rows get `get_row_style`, which composes alternating `row_styles` with any per-row style ([`L823-L828`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L823-L828), [`L310-L318`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L310-L318)). Neither is set here.

Each cell is then rendered on its own, at its own width ([`L829-L844`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L829-L844)): the options are updated with `width`, the column's `justify`, `no_wrap`, `overflow` and `highlight`, and `console.render_lines` is called with `style=get_style(cell.style) + row_style`. This is where the strings finally stop being strings. `Padding.__rich_console__` renders its inner renderable at `width - left - right` ([`padding.py#L92-L99`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/padding.py#L92-L99)), which routes `'Date'` through `Console.render` → `render_str` → `markup.render` exactly as in Chapter 2 — markup still enabled, highlighting now off. The column's `justify` is applied by `Lines.justify`, which pads left-aligned cells on the right and right-aligned ones on the left ([`containers.py#L129-L142`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/containers.py#L129-L142)).

The segments this produces are visible the moment `print` takes them: `Segment('┃', Style())`, then `Segment(' ', Style(magenta, bold))`, `Segment('Date        ', Style(magenta, bold))` — four characters plus eight of justification, filling 14 minus 2 of padding — then the right pad, then `Segment('Title                            ', …)` at 33 cells, `Segment('Production Budget', …)` at exactly 17, and `Segment('    Box Office', …)` right-justified into 14. The padding spaces carry the cell style because `render_lines` applies it to every segment it produces ([`console.py#L1372-L1373`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1372-L1373)), which is what makes a background colour fill the whole cell rather than just the glyphs.

Further down, `Segment('Solo', …)` and `Segment('$1,332,539,889', …)` appear — the markup in those cells was interpreted here, into their own spans, inside the cell render.

> **For the owner:** Table cells are parsed as console markup. `'[red]Solo[/red]'` became styled text; a cell containing user-supplied text with square brackets will be interpreted the same way, and an unbalanced tag raises `MarkupError` out of `console.print`, turning a table into an exception. Wrap untrusted cell values in `rich.markup.escape()` or pass them as `Text` objects.

Rows are then squared off. `align_cell` pads a cell vertically to the row height — forced to `bottom` for the header and `top` for the footer, otherwise the column's `vertical` — and `Segment.set_shape` fixes every cell to the same width and height ([`table.py#L846-L877`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L846-L877)). That is the guarantee that the vertical bars line up even when one cell wraps to three lines and its neighbours do not. The dividers between cells come from `box_segments`, choosing head/mid/foot characters by row position, and a divider made of whitespace is re-styled with the row's background so zebra striping has no gaps ([`L885-L904`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L885-L904)). After the header row, `get_row(widths, "head")` draws the `┡━━━╇…┩` rule ([`L910-L914`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L910-L914)), and the last thing the generator yields is `get_bottom(widths)` ([`L933-L935`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L933-L935)) — the `└───…┴────────────────┘` the final output ends with.

> **For the owner:** A cell wider than its column is not an error. `Column.overflow` defaults to `"ellipsis"` ([`table.py#L90-L91`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L90-L91)) and is passed into each cell's render options ([`L830-L837`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L830-L837)), so content is truncated with a `…` and the layout holds. Set `overflow="fold"` on any column whose values must survive in full.

> **Leaves as:** a stream of `Segment`s beginning `Segment('┏━━━━━━━━━━━━━━┳…┓', Style())`, `Segment('\n')`, `Segment('┃', Style())`, `Segment(' ', Style(magenta, bold))`, `Segment('Date        ', Style(magenta, bold))`, … and ending with the bottom border
