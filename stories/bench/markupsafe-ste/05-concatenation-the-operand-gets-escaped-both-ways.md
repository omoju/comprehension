> **For the owner:** This operator carries the main guarantee for everyday code. Safe markup plus untrusted text gives safe markup, because `__add__` escapes the right operand every time. `Markup.__radd__` does the same work for the other direction, and escapes the left operand first ([`__init__.py:142-146`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L142-L146)). The order of the operands does not change the result.

The second `+` has a `Markup` on the right. `Markup("</footer>")` is built at trace line 74, and `__add__` runs again at line 76. The guard accepts the value, and `Markup.escape` runs again at line 77. This time `escape` sees a `Markup`, so `type(s) is str` is false and the `__html__` branch wins ([`__init__.py:42-43`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L42-L43)). `Markup.__html__` returns `self` ([`__init__.py:133-134`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L133-L134)), so `</footer>` stays a live tag. Trace line 88 shows the complete footer, `Markup('<footer>&lt;/p&gt; &amp; &lt;script&gt;oops&lt;/script&gt;</footer>')`. The scenario printed it through `Markup.__repr__` at line 90 ([`__init__.py:167-168`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L167-L168)).

One road stays unused in this run. An operand that is not a `str` and has no `__html__` makes `__add__` return `NotImplemented` ([`__init__.py:140`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L140)). Python then raises `TypeError`. An integer added to a `Markup` fails loudly, and the library does not convert it to text in silence.

The same pattern covers the rest of the `str` methods on `Markup`. `join` escapes every element of the iterable ([`__init__.py:170-171`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L170-L171)). `replace` escapes only its `new` argument ([`__init__.py:257-258`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L257-L258)). `ljust`, `rjust` and `center` escape the fill character ([`__init__.py:260-264`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L260-L264), [`__init__.py:272-273`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L272-L273)). `strip`, `lstrip`, `rstrip`, `removeprefix`, `removesuffix` and `partition` do not escape their arguments ([`__init__.py:266-276`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L266-L276), [`__init__.py:297-311`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L297-L311)). Version 3.0.0 made that difference on purpose, because these methods search text and do not insert text ([`CHANGES.rst:55-60`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/CHANGES.rst#L55-L60)).

> **For the owner:** Caution: the slice methods keep the type but can break the text. `__getitem__`, `split`, `rsplit` and `splitlines` return `Markup` pieces ([`__init__.py:242-243`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L242-L243), [`__init__.py:173-186`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L173-L186)). A slice can cut an entity such as `&amp;` in half. The result is still typed as safe, but the markup is malformed. Check any code that truncates a `Markup` for display, for example a preview or a summary.
