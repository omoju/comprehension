`striptags` first makes a plain copy of the text with `value = str(self)` ([`__init__.py:206`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L206)). It then runs 2 separate loops. The first loop removes HTML comments ([`__init__.py:212-217`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L212-L217)). The code comment above the loops gives the reason for the order ([`__init__.py:208-210`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L208-L210)). A comment that contains a tag would end too early in a single pass, and part of the comment would stay in the output. Our page has no comment, so `find("<!--")` returns `-1` and the loop stops at once.

The second loop removes the tags ([`__init__.py:220-224`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L220-L224)). It finds each `<`, finds the next `>`, and cuts out the span between them. The `<p>`, `<a href="/user/3">`, `<span class="user">` and their closing tags go away. The escaped text stays, because `&lt;script&gt;` holds no literal `<` character. The last step joins the words with single spaces ([`__init__.py:227`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L227)). The value is now `'User: Alice &#34;The &lt;b&gt;Great&lt;/b&gt;&#34; said: &lt;script&gt;alert(document.cookie);&lt;/script&gt;'`, which the trace shows at line 95.

> **For the owner:** Caution: `striptags` is best-effort text extraction, and not a sanitizer. An unterminated `<!--` or an unterminated `<` makes the loop `break` and leaves the rest of the text in place ([`__init__.py:214-215`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L214-L215), [`__init__.py:221-222`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L221-L222)). Both loops use `find` and not regular expressions. Version 2.1.4 made that change to remove a performance problem ([`CHANGES.rst:75-81`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/CHANGES.rst#L75-L81)). Large input therefore cannot blow up the run time.

The final line of `striptags` wraps the stripped value and calls `unescape` on it ([`__init__.py:228`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L228)). Trace line 95 records that wrap, and trace line 97 records the call to `Markup.unescape`. `unescape` imports `html.unescape` and applies it to `str(self)` ([`__init__.py:188-197`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L188-L197)). Every entity turns back into its character. `&#34;` becomes `"`, `&lt;b&gt;` becomes `<b>`, and `&lt;script&gt;` becomes `<script>`. Trace lines 98 and 99 show the result: `'User: Alice "The <b>Great</b>" said: <script>alert(document.cookie);</script>'`.

The data has now left the safe side. The annotation on `unescape` says `-> str`, and the annotation on `striptags` says `-> str` ([`__init__.py:188`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L188), [`__init__.py:199`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L199)). The returned value is a plain `str` and holds a live `<script>` tag again. The scenario only prints it, which is safe. The page object itself did not change, because `striptags` worked on a copy.

> **For the owner:** These 2 methods are the documented exit from safety, and the return type is the only warning. In review, find every place where the output of `striptags` or `unescape` flows back into HTML. Each such place needs a new call to `escape`. Also find every call to `Markup(...)` whose argument is not a developer-written literal, because the constructor marks any text safe.

The scenario then builds the expected fragment, at trace lines 100 and 101. This is the same unguarded constructor, used on text the author controls. The comparison succeeds, and the checks `isinstance(page, Markup)` and `"<script>" not in page` hold. They hold by construction, and not by inspection of the output.

State the guarantee plainly. Text that passes through `escape` has the 5 characters `&`, `>`, `<`, `'` and `"` replaced, and carries the type `Markup` ([`_native.py:1-8`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/_native.py#L1-L8)). The methods `format`, `%`, `+`, `join`, `replace`, `ljust`, `rjust` and `center` route their inserted values through that same `escape`. A value that is already a `Markup` passes through unchanged, so no path escapes it twice. The C version and the pure-Python version do the same work, and the test suite runs against both ([`conftest.py:26-39`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/tests/conftest.py#L26-L39)). A missing C extension changes speed only.

> **For the owner:** Here are the limits to weigh before you sign off. First, `Markup(text)`, `__html__` and `__html_format__` are trusted without any check ([`__init__.py:125-126`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L125-L126), [`__init__.py:340-349`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L340-L349)). Second, only 5 characters are escaped, so unquoted attributes, `javascript:` URLs, and text inside `<script>` or `<style>` are out of scope. Third, `striptags` and `unescape` return unsafe `str`, and a slice can cut an entity in half. Fourth, `escape` can call a user `__html__` twice per call. Two helpers reduce common mistakes at the edge: `escape_silent(None)` gives `Markup('')` where `escape(None)` gives `Markup('None')` ([`__init__.py:48-61`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L48-L61)), and `soft_str` converts to text without destroying an existing `Markup` ([`__init__.py:64-81`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L64-L81)).
