# Chapter 1 · The Trust Boundary, and the Unguarded Door Beside It

> **Enters as:** `'<script>alert(document.cookie);</script>'` — a plain `str` of unknown origin

The engine was chosen before the string arrived. At import time the module tries to load `_escape_inner` from the compiled C extension `_speedups`, and falls back to the pure-Python `_native` module if that import fails ([`__init__.py:7-10`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L7-L10)). Both versions replace the same five characters, so the choice changes speed only. The string itself knows none of this. It is a comment that somebody posted, and it contains a cross-site scripting payload.

`escape` receives it as the single positional argument `s` ([`__init__.py:24-45`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L24-L45)). The first test is `type(s) is str` ([`__init__.py:39-40`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L39-L40)). The comment is an exact `str`, so it takes this fast path and skips the `__html__` check below it. The code uses `type(s)` and not `isinstance(s, str)` on purpose. The comment in the source says a proxy object can report the `__class__` of the value it wraps ([`__init__.py:35-38`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L35-L38)). An `isinstance` test would let such an object through unescaped.

`_escape_inner` then does the work. The pure-Python version chains five calls to `str.replace` ([`_native.py:1-8`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/_native.py#L1-L8)). It replaces `&` first, before the four replacements that introduce new `&` characters; the reverse order would escape every entity twice. The C version scans the string, counts the extra length, and returns the input object unchanged when nothing needs escaping ([`_speedups.c:84-87`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/_speedups.c#L84-L87)). Our comment needs escaping. It leaves this step as `'&lt;script&gt;alert(document.cookie);&lt;/script&gt;'`, still a plain `str`.

> **For the owner:** `escape` replaces exactly 5 characters: `&`, `>`, `<`, `'`, `"`. It does not replace the backtick, the equals sign, or whitespace. The output is therefore safe in element text and inside quoted attribute values. It is not sufficient for unquoted attributes, for `javascript:` URLs, or inside `<script>` and `<style>` blocks. Check that your templates quote all attribute values.

`Markup.__new__` receives the escaped text next, with `encoding=None` and `errors='strict'` ([`__init__.py:122-131`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L122-L131)). The constructor performs no escaping at all. It first checks for an `__html__` attribute on the object, which a plain `str` does not have. Then, because `encoding` is `None`, it calls `str.__new__(cls, object)` and returns. The road not taken is the decode road: a non-`None` `encoding` forwards `encoding` and `errors` to `str.__new__` for bytes input. The value now leaves the call as `Markup('&lt;script&gt;alert(document.cookie);&lt;/script&gt;')`. Its safety is its type and nothing else, because `Markup` declares `__slots__ = ()` and stores no flag ([`__init__.py:120`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L120)).

> **For the owner:** `Markup(text)` marks any text as safe without a check. This is the unguarded door next to the trust boundary. The guarantee runs in one direction only: output of `escape` is safe, input of `Markup` is the responsibility of the application author. In review, treat every `Markup(...)` call whose argument is not a developer-written literal as a finding.

The scenario then printed the value. `Markup.__repr__` calls `str.__repr__` and wraps the result in the class name ([`__init__.py:167-168`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L167-L168)). It returned `"Markup('&lt;script&gt;alert(document.cookie);&lt;/script&gt;')"`. A `Markup` is therefore visible as such in logs and in a REPL, and a reader can tell it apart from a `str`.

The same value went back into `escape` one more time, to show that escaping is idempotent. This time the road is different. `Markup` is a subclass of `str`, so `type(s) is str` is false, and the second test, `hasattr(s, "__html__")`, wins ([`__init__.py:42-43`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L42-L43)). `Markup.__html__` returns `self` ([`__init__.py:133-134`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L133-L134)). `escape` passes that result to `Markup(...)`, and the constructor checks the result for `__html__` and calls it again ([`__init__.py:125-126`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L125-L126)). The trace shows `Markup.__html__` twice for this one `escape` call: once from `escape`, once from `Markup.__new__` on the value it got back. The five replacements never run on this value again, so the entities stay single-escaped and the result equals the input.

> **For the owner:** `escape` calls `__html__` on the object, and `Markup.__new__` then calls `__html__` on the value that method returned. A class whose `__html__` returns a plain `str` is called 1 time. A class whose `__html__` returns another object with `__html__` causes a second call on that object. Require `__html__` implementations to be pure and cheap, with no side effects.

A third road exists and this run did not take it. An object that is neither an exact `str` nor an object with `__html__` reaches the last line, `Markup(_escape_inner(str(s)))` ([`__init__.py:45`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L45)). That road converts the object with `str()` first. It is also the reason why `escape(None)` gives `Markup('None')`, and why the library provides `escape_silent` for optional values ([`__init__.py:48-61`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L48-L61)).

> **Leaves as:** `Markup('&lt;script&gt;alert(document.cookie);&lt;/script&gt;')`, and the same value again after a second trip through `escape`
