# Chapter 1 · The World the Data Enters

> **Enters as:** `Console(color_system='auto', force_terminal=None, soft_wrap=False, theme=None, file=None, quiet=False, width=100, height=None, style=None, no_color=None, tab_size=8, record=True, markup=True, emoji=True, highlight=True, log_time_format='[%X]', highlighter=ReprHighlighter(), legacy_windows=None, safe_box=True, _environ=None)`

The data has not arrived yet. Two short strings — `'Hello'` and `'World!'` — are still just literals in the caller's source, and the table is not even built. What exists first is the machine they will travel through, and that machine is assembled in a single constructor call before anything is printed.

The caller asks for very little: a width of 100 and `record=True`. Everything else is a default, and the defaults are where the interesting decisions live.

The first question the constructor asks is *where am I running*. `_is_jupyter()` looks for a `get_ipython` name in the global scope; there is none, so it returns `False` on a `NameError` without raising ([`console.py#L505-L522`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L505-L522)). Had it returned `True`, the width and height would have been taken from `JUPYTER_COLUMNS` / `JUPYTER_LINES` or defaulted to 115×100 ([`L657-L670`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L657-L670)). It didn't, so the caller's `width=100` stands untouched.

Next, `detect_legacy_windows()` — `WINDOWS and not get_windows_console_features().vt` ([`L576-L578`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L576-L578)) — returns `False`, so `legacy_windows` is `False` ([`L678-L682`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L678-L682)). That flag matters later than you'd think: it is subtracted from the console width, it is passed to every box-drawing decision, and it chooses between the win32 API renderer and an ordinary `file.write` at the very end.

Because `width` was given explicitly, the block that reads `COLUMNS` from the environment is skipped ([`L684-L691`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L684-L691)), and `Console.size` will short-circuit to the stored value rather than calling `os.get_terminal_size` ([`L1012-L1013`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1012-L1013)). From here on, "100 cells wide" is a fact about this object, not about the terminal it happens to be attached to. That is a deliberate guarantee, and it is what makes the scenario's output reproducible.

Then comes the decision that quietly governs every style in the run. `color_system='auto'` sends the constructor into `_detect_color_system` ([`L707-L712`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L707-L712)), which immediately asks `is_terminal` ([`L789-L811`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L789-L811)). `is_terminal` works down a list of overrides in order: an explicit `force_terminal`, an Idle check, Jupyter, the `TTY_COMPATIBLE` variable (`"0"` forces false, `"1"` forces true), `FORCE_COLOR`, and only then `file.isatty()` ([`L930-L976`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L930-L976)). To reach `isatty` it must first resolve `file`, which is `sys.stdout` here, possibly unwrapped from a `rich_proxied_file` and falling back to a null sink if it is `None` ([`L756-L763`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L756-L763)). The trace records the answer: `<_io.TextIOWrapper name='<stdout>' mode='w' encoding='utf-8'>`, and `isatty()` is `False`.

Not a terminal, therefore `_detect_color_system` returns `None` ([`L793-L794`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L793-L794)), and `self._color_system` is `None`. The `'bold red'` the caller is about to pass will still be parsed into a real `Style` and carried the entire length of the pipeline — but at the final step `Style.render` returns its text unchanged whenever `color_system is None` ([`style.py#L710-L711`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/style.py#L710-L711)). The colour is decided here, once, at construction, by sniffing the output file.

> **For the owner:** Colour is auto-detected at construction, not at write time, so redirecting the console's `file` afterwards will not re-run the detection. If you need colour in a pipe or a CI log, set `force_terminal=True` on the constructor or set `FORCE_COLOR` / `TTY_COMPATIBLE=1` in the environment ([`console.py#L955-L966`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L955-L966)). Note also that `is_terminal` swallows a `ValueError` from `isatty()` on a closed file and reports "not a terminal" rather than raising ([`console.py#L969-L976`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L969-L976)).

The remaining construction is bookkeeping, but two pieces matter. A `LogRender` is built from the logging defaults — `show_time=True`, `show_path=True`, `time_format='[%X]'` — and stashed on the console ([`L715-L719`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L715-L719), [`_log_render.py#L15-L30`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/_log_render.py#L15-L30)). Our data never touches it — `print` does not use `LogRender`; only `log` does — but it is constructed eagerly either way. And a `ThemeStack` is wrapped around `themes.DEFAULT` inside a `ConsoleThreadLocals` ([`L745-L747`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L745-L747), [`theme.py#L88-L91`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/theme.py#L88-L91)). That stack holds every named style — `repr.number`, `table.header`, `log.time` — and it is *thread-local*, alongside the output buffer and buffer index, so two threads printing to the same console get independent buffers and independent theme stacks.

Finally, because `record=True`, `self._record_buffer` is created empty and a second lock, `_record_buffer_lock`, is created to guard it ([`L744-L748`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L744-L748)). Nothing is recorded yet. The scenario's closing `console.export_text()` depends on this flag having been set *before* any printing happened; it cannot be enabled retroactively.

> **For the owner:** `record=True` makes the console keep a copy of every segment it writes, appended under `_record_buffer_lock` and never trimmed except by an `export_*` call ([`console.py#L2063-L2065`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L2063-L2065)). Do not enable it on a long-lived console unless something drains it; memory growth is proportional to total output.

The object the data will meet is now fixed: 100 cells wide, writing to stdout, encoding `utf-8`, markup on, emoji on, highlighting on, colour off, recording on. The strings can arrive.

> **Leaves as:** a `Console` with `_color_system = None`, `legacy_windows = False`, `is_jupyter = False`, `_width = 100`, `record = True`, an empty `_record_buffer`, a `LogRender(show_time=True, show_path=True, time_format='[%X]')`, a default-themed `ThemeStack`, and `file` resolving to `<_io.TextIOWrapper name='<stdout>' mode='w' encoding='utf-8'>`
