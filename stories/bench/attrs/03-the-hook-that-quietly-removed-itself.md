# Chapter 3 · The Hook That Quietly Removed Itself

> **Enters as:** `_Attributes(attrs=(Attribute(name='a_number', …), Attribute(name='list_of_numbers', …)), base_attrs=[], base_attrs_map={})` returning into `_ClassBuilder.__init__`, alongside the `ClassProps` record from chapter 1

The two `Attribute`s come back up the call and land in a builder that has, so far, nothing but a name. Over the next thirty lines of `__init__` the builder copies the policy out of `ClassProps` into its own slots — [`self._slots = props.is_slotted`, `self._frozen = props.is_frozen`, `self._cache_hash = props.hashability is HASHABLE_CACHED`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L693-L718) — and takes a snapshot of the class it was given: [`self._cls_dict = dict(cls.__dict__) if props.is_slotted else {}`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L694). For a slotted class that snapshot is not a scratch pad; it is the seed of the replacement type that chapter 5 will build. `hard_math` rides along inside it.

It also looks for the two initialization hooks. [`getattr(cls, "__attrs_pre_init__", False)`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L705-L715) and the same for `__attrs_post_init__` both come back falsy — `SomeClass` defines neither — so no `inspect.signature` call is made and both flags stay `False`. That is why the trace shows nothing between the `_transform_attrs` return and `_make_getstate_setstate`.

Two entries go onto the class dict immediately: [`__attrs_attrs__` and `__attrs_props__`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L723-L724). The first is the `SomeClassAttributes` tuple from the last chapter; it is the entire public introspection surface that `fields()`, `has()`, and every third-party tool will read. The second is the policy record itself, which is what `attrs.inspect()` hands back later.

## The hook that was installed, then wasn't

Then comes the branch that matters most for anyone reviewing this class's runtime behaviour. The class isn't frozen, so the `_frozen_setattrs` path is skipped and the builder falls into the [`elif self._on_setattr in (_DEFAULT_ON_SETATTR, setters.validate, setters.convert)`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L731-L756) arm. Chapter 1's `define` wrapper put `pipe(convert, validate)` here on the grounds that mutable classes should re-run converters and validators on every assignment. Now the builder checks whether there is any work for that hook to do: it loops over the two attributes looking for a non-`None` `validator` or `converter`, breaking early if it finds both.

It finds neither. `a_number` has `validator=None, converter=None`; so does `list_of_numbers`. The condition `self._on_setattr == _DEFAULT_ON_SETATTR and not (has_validator or has_converter)` holds, and the builder sets `self._on_setattr = None`. The comment is blunt about the reasoning: *"If class-level on_setattr is set to convert + validate, but there's no field to convert or validate, pretend like there's no on_setattr."* The `ClassProps` record still reports `on_setattr_hook=<wrapped_pipe>` — only the builder's working copy was cleared.

> **For the owner:** The convert-and-validate-on-assignment guarantee that `@define` advertises is decided once, at class-creation time, and is dropped entirely when no field declares a converter or validator. The shortcut recognizes only the three built-in hooks by equality — a custom `on_setattr` callable is always kept — so if you later attach a validator to an `Attribute` by hand, nothing will run it, because this class has no `__setattr__` of its own. Add validators in the class body, not afterwards.

Because `props.added_pickling` is `True` (chapter 1 derived it from `slots=True`), the builder calls `_make_getstate_setstate`, which the trace records returning the pair `slots_getstate` / `slots_setstate`. Both close over [`state_attr_names`, the field names minus `__weakref__`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1030-L1032), because that slot isn't writable. `slots_getstate` returns a plain dict of name to value. `slots_setstate` accepts [either a tuple — for pickles written by *attrs* before v22.2.0 — or a dict, in which case it sets only the names actually present](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1042-L1055).

> **For the owner:** `slots_setstate` skips state keys it doesn't find rather than raising, so a slotted instance restored from an old or truncated pickle comes back with some slots simply unset; the failure surfaces much later as an `AttributeError` on first read. If you pickle these classes across versions, assert on the full field set after loading.

Finally `__init__` decides how methods will be stamped: since the class has both `__module__` and `__qualname__`, [`self._add_method_dunders = self._add_method_dunders_unsafe`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L770-L777) — the variant that assigns without `contextlib.suppress`. The builder is ready.

## Three strings and a `None`

Back in `attrs.wrap`, the builder is now driven method by method, in the order the flags were resolved.

`add_repr(None)` calls `_make_repr_script`, which returns a source string and a globals dict. The trace's truncated return shows both: a script beginning `def __repr__(self):\n  try:\n    alre…` and globs `{'AttributeError': …, 'NOTHING': NOTHING, '_compat': <module 'attr._compat'>}`. The generated function doesn't just interpolate fields. It [opens with a lookup of `_compat.repr_context.already_repring`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1888-L1904) — a thread-local set of `id(self)` values — and if this instance is already being repr'd somewhere up the stack, it returns `'...'` instead of recursing forever. The thread-local deliberately [lives in `_compat` rather than `_make`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_compat.py#L83-L95) so the generated functions don't hold a direct reference to it, which would break cloudpickle.

Two details in that script are worth knowing. The class name is rendered from [`self.__class__.__qualname__`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1883-L1886), so a subclass reprs under its own name, not the one it inherited the method from. And a field with `init=False` is read via [`getattr(self, name, NOTHING)`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1871-L1880) rather than `self.name`, so an unset slot reprs as `NOTHING` instead of raising. Nothing is compiled yet: `add_repr` [appends `(script, globs, _attach_repr)` to `self._script_snippets`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1004-L1012) and sets `_repr_added = True` — a flag that only exists so `add_str` can refuse to run without it. `added_str` is `False`, so `add_str` is never called.

`add_eq` does the same for equality. `_make_eq_script` returns a script whose first act is a type check:

```
def __eq__(self, other):
    if other.__class__ is not self.__class__:
        return NotImplemented
```

then a single `and`-chain over the fields — `self.a_number == other.a_number and self.list_of_numbers == other.list_of_numbers` — [built field by field](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1746-L1770). A `__ne__` is not generated; `add_eq` [assigns the one shared module-level function](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1158-L1161), which calls `self.__eq__(other)` and [forwards `NotImplemented` rather than inverting it](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1730-L1739). That function is the only piece of *attrs* that the scenario's instances will call at runtime.

> **For the owner:** Equality here is type-exact by design: `other.__class__ is not self.__class__` returns `NotImplemented`, so a subclass instance never compares equal to a base instance with identical field values, and Python then falls back to identity. If your domain expects a subclass to be substitutable in an equality test, this class will not give you that.

`add_setattr` runs next, because the class isn't frozen. It walks the fields building `sa_attrs` from [`a.on_setattr or self._on_setattr`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1175-L1186) — and both halves are now `None`, the class-level half because of the removal thirty lines earlier. `sa_attrs` stays empty, and the method returns on the spot. **No `__setattr__` is written at all.** Assignment on these instances is an ordinary slot write with no interposition. Had there been even one hook, the generated `__setattr__` would have looked up the field in a dict, [checked whether the hook is a generator function and if so driven it around the assignment](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1194-L1222) — and would have [refused outright if the user had their own `__setattr__`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1188-L1191).

The last step in this span is hashing. `props.is_hashable` is read — it is `True` only for [`HASHABLE` or `HASHABLE_CACHED`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L3056-L3061) — and returns `False`. The `hashability` is `UNHASHABLE`, so [`make_unhashable`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1066-L1068) writes a single entry: `self._cls_dict["__hash__"] = None`. `hash(sc)` will raise `TypeError`, which is Python's own rule for a class that customizes equality. Note what this *isn't*: *attrs* only adds. If a base class had defined a real `__hash__`, this `None` shadows it on `SomeClass` but leaves the ancestor untouched.

The builder now holds a finished class dict and three unevaluated strings.

> **Leaves as:** a `_ClassBuilder` with `_on_setattr = None`, `_wrote_own_setattr = False`, `_repr_added = True`, a `_cls_dict` carrying `__attrs_attrs__`, `__attrs_props__`, `__getstate__`, `__setstate__`, `__ne__` and `__hash__ = None` (and no `__setattr__`), plus two queued `_script_snippets` holding the `__repr__` and `__eq__` sources
