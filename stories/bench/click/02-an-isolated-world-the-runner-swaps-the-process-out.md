# Chapter 2 · An isolated world: the runner swaps the process out from under you

> **Enters as:** `input='Click\n'`, `args=['--count=3']`, `env=None`, `color=False` — a string of keystrokes that has not yet been typed, and a command line that has not yet been read

The command is built. What it needs now is a world to run in: a stdin that will answer its prompt, a stdout that can be read back afterwards, and an environment that is not the test runner's own. `CliRunner` manufactures that world, and it does so by reaching into process-global state and swapping it out.

The runner itself is cheap. [`CliRunner.__init__` validates the capture mode first](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L368-L375) — anything other than `'sys'` or `'fd'` is a `ValueError`, and `'fd'` is rejected outright on Windows — then [stores five settings](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L376-L380). For this run they are the defaults: `charset='utf-8'`, `env={}`, `echo_stdin=False`, `catch_exceptions=True`, `capture='sys'`.

`invoke` is called with the command, the argument list, and the input string. Before entering isolation it checks whether file-descriptor capture was requested; [`capture == 'fd'` would start two `_FDCapture`s on fds 1 and 2](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L657-L664). Here it is `'sys'`, so `cap_out` and `cap_err` stay `None` and the real file descriptors of the host process are never touched. Then [`with self.isolation(input=input, env=env, color=color)`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L666) opens the door.

## The keystrokes become bytes

`'Click\n'` is the first thing isolation handles. [`make_input_stream`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L211-L228) looks for a `read` attribute, finds none on a `str`, and so [encodes it with the runner's charset and wraps it in a `BytesIO`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L223-L228). The input is now `b'Click\n'` sitting in a buffer at position zero, waiting for something to read a line from it. (Had a real file object been passed, it would have been unwrapped to its binary reader instead, or rejected with a `TypeError` if it had none.)

Before anything is replaced, the current values are captured: [`old_stdin`, `old_stdout`, `old_stderr` and `old_forced_width`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L435-L439), with `formatting.FORCED_WIDTH` immediately pinned to `80` so help output does not vary with the terminal that happens to be running the tests. [`make_env`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L389-L396) copies the runner's own environment overrides and merges the per-call ones; with both empty it returns `{}`.

## Three buffers, one of them shared

[`StreamMixer()` creates a plain `BytesIO` called `output`, then two `BytesIOCopy` buffers that both copy into it](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L150-L153). `BytesIOCopy` is four lines of mechanism with one guarantee in it: [`write` appends to the shared buffer before appending to itself](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L133-L135), and [`flush` flushes both](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L129-L131). Because the mixing happens at write time rather than by concatenating two logs afterwards, the shared buffer records the true order in which stdout and stderr were written — which is why the prompt echo will later appear ahead of the greetings in the result the test asserts on.

Over those buffers go three text wrappers. [`sys.stdin` becomes a `_NamedTextIOWrapper` over the input bytes](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L450-L452), [`sys.stdout` over the stdout copy](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L459-L464), and [`sys.stderr` over the stderr copy with `errors="backslashreplace"`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L466-L472) — so a command that writes undecodable bytes to stderr produces escapes rather than an exception during the test.

Each wrapper carries [`_original_fd = -1`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L182), and [`fileno()` only returns a real descriptor when that field is non-negative](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L192-L200). In `'sys'` mode it stays `-1`, so `sys.stdout.fileno()` raises `io.UnsupportedOperation`. That is deliberate: it stops code under test from calling `os.dup2` on the "stdout" fd and clobbering the host test runner's real output. In `'fd'` mode `invoke` would [point `_original_fd` at the saved pre-redirection descriptor](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L670-L672) so C-level consumers keep working.

> **For the owner:** The default `capture='sys'` records only Python-level writes, so output from C extensions, subprocesses, or a stale reference to the old `sys.stdout` is not captured and `fileno()` raises. Choose `capture='fd'` for commands that shell out or write from native code, and note it is unavailable on Windows ([docstring](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L331-L338)).

## The hooks the command will reach for

Streams alone are not enough: a prompt does not go through `sys.stdout.write` in Click, it goes through a module-level function. So isolation defines [`visible_input`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L474-L483), which writes the prompt, pulls one line from the text-wrapped input, strips the newline, echoes it back and flushes — the behaviour a terminal would have given for free. Alongside it are [`hidden_input`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L485-L492), [`_getchar`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L494-L502) and a [`should_strip_ansi` that ignores the stream entirely and answers from the `color` argument](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L504-L511) — `color=False`, so it will answer `True` and colour codes will be stripped.

Then the swap: [six module attributes are saved and overwritten](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L513-L523), including `should_strip_ansi` in *both* the `utils` and `_compat` namespaces, because each module imported its own reference. [`pdb.Pdb.__init__` is patched too](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L525-L562), defaulting the debugger to `sys.__stdin__`/`sys.__stdout__` so a `breakpoint()` inside a command talks to the real terminal instead of reading from an empty `BytesIO`; debuggers that do not subclass `pdb.Pdb` are not covered.

Last, [each environment key is recorded in `old_env` before being set or deleted](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L564-L574) — the record is taken *before* the mutation, so restoration can distinguish "was absent" from "was empty". With nothing to override, the loop does nothing and [the generator yields the three buffers](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L575).

> **For the owner:** Everything isolation touches is process-global — the standard streams, `os.environ`, Click's prompt hooks, the ANSI policy, and `pdb`. [The class documents that it works only in single-threaded use](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L317-L322). Parallelise tests that use `CliRunner` with processes, not threads.

Inside the new world, `invoke` finishes its preparation. The argument list is already a list, so [the `shlex.split` branch for string arguments](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L678-L679) is skipped. No `prog_name` was passed in `extra`, so [the fallback runs](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L681-L684) and [`get_default_prog_name` returns the command's own name](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/testing.py#L382-L387): `'hello'`. The argument list `['--count=3']` is about to be handed to `Command.main`.

> **Leaves as:** `outstreams = (BytesIOCopy stdout, BytesIOCopy stderr, BytesIO output)` with both copies mirroring into the third; `sys.stdin` reading `b'Click\n'`, `sys.stdout`/`sys.stderr` writing into the copies, `FORCED_WIDTH == 80`, the prompt and ANSI hooks replaced; `args == ['--count=3']` and `prog_name == 'hello'`
