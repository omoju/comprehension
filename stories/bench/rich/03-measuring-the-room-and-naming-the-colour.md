# Chapter 3 · Measuring the Room and Naming the Colour

> **Enters as:** `[<text 'Hello World!' [] ''>]` held inside `print`, with `style='bold red'` still an uninterpreted string and no idea yet how wide the world is

The joined `Text` is sitting in a local list. Before anything renders it, `print` has to answer two questions on its behalf: how much room there is, and what `'bold red'` actually means. Both answers are computed fresh, here, on every call.

## How wide is the world

`print` asks `self.options` ([`console.py#L1716`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1716-L1724)). That property is small but it pulls on three others ([`L990-L1002`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L990-L1002)).

First `Console.size` ([`L1004-L1043`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1004-L1043)). The scenario pinned `width=100` but left height alone, so the fast path at [`L1012-L1013`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1012-L1013) — which requires *both* to be set — is skipped. `is_dumb_terminal` is consulted next ([`L1015-L1016`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L978-L988)), and the trace shows it reaching all the way down through `is_terminal` to `Console.file` and back with `False` — the same `<_io.TextIOWrapper name='<stdout>'>` and the same `False` as in Chapter 1, recomputed from scratch because none of these are cached. Then the method queries `os.get_terminal_size` on each standard stream ([`L1021-L1028`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1021-L1028)), swallowing `AttributeError`, `ValueError` and `OSError`, and then lets `COLUMNS` and `LINES` from the environment override whatever it found ([`L1030-L1035`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1030-L1035)). None of that matters for width: the final return re-asserts the explicit `self._width` and only falls back to the detected value when it is `None` ([`L1038-L1043`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1038-L1043)). The trace records the answer: `ConsoleDimensions(width=100, height=25)` — 100 because the caller said so, 25 because nothing could be detected and `height or 25` took over.

Then `Console.encoding` ([`L921-L928`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L921-L928)) reads `.encoding` off the file object and lowercases it, defaulting to `'utf-8'` twice over — once if the attribute is missing, once if it is present but falsy. Here stdout reports `utf-8`. That string is not decoration: `ConsoleOptions.ascii_only` is defined as `not self.encoding.startswith("utf")` ([`L142-L145`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L142-L145)), and that is the flag the table's box characters will consult in Chapter 8.

The result is one `ConsoleOptions` dataclass: `size=(100, 25)`, `legacy_windows=False`, `min_width=1`, `max_width=100`, `is_terminal=False`, `encoding='utf-8'`, `max_height=25`, and every content override (`justify`, `overflow`, `highlight`, `markup`, `height`) `None`, with `no_wrap` at its dataclass default of `False`.

## A copy for the journey

`print` immediately calls `update` on it ([`L157-L192`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L157-L192)). The trace shows what arrives: `width`, `min_width` and `max_width` are the sentinel `NoChange` instance, and `justify`, `overflow`, `no_wrap`, `highlight`, `markup`, `height` are all literal `None`. That distinction is the whole design of the method — `None` is a *value* that means "no override", and `NO_CHANGE` is the only way to say "leave it alone". So the three width fields survive untouched while `no_wrap` is actually overwritten, going from `False` to `None`. (That is why the very next thing the `Text` meets, `pick_bool(self.no_wrap, options.no_wrap, False)`, falls through two `None`s to the literal `False` at trace line 175.)

The first line of `update` is `options = self.copy()` ([`L171`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L171)), and `copy` builds a new instance with a shallow-copied `__dict__` ([`L147-L155`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L147-L155)). Every option-narrowing method in the file does this. It is the reason a nested renderable — a cell inside a table inside a panel — cannot widen or re-justify its parent by mutating what it was handed.

The road not taken sits one line below, at [`L1719`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1719): had the caller passed `width=200`, it would have been clamped by `min(width, self.width)` before reaching `update`. The console width is a ceiling a caller can lower but not raise.

> **For the owner:** `max_width` is advice, not enforcement. It is copied down the render tree and well-behaved renderables respect it, but nothing in `ConsoleOptions` stops a third-party `__rich_console__` from emitting a 400-cell line. The actual guarantee is the crop in Chapter 5, which runs over the finished segments regardless of who produced them — and which `soft_wrap=True` or `crop=False` switches off. If you accept custom renderables from elsewhere, keep `crop` at its default.

## Naming the colour

Because `style` is not `None`, `print` resolves it before rendering ([`L1733`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1729-L1741)). `Console.get_style('bold red')` ([`L1470-L1498`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1470-L1498)) first asks the thread-local `ThemeStack` ([`theme.py#L88-L91`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/theme.py#L88-L91)), whose `get` is bound directly to the top dict's `.get`. `'bold red'` is a *definition*, not a theme name like `repr.number`, so the lookup returns `None` and the string falls through to `Style.parse` ([`L1489-L1492`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1488-L1492)).

`Style.parse` ([`style.py#L496-L561`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/style.py#L496-L561)) is a word-by-word state machine: `on` consumes the next word as a background colour, `not` negates the following attribute, `link` takes a URL, a word in `STYLE_ATTRIBUTES` sets a flag, and anything else must parse as a colour. `'bold'` is in the attribute table ([`L549-L550`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/style.py#L549-L550)); `'red'` falls to the final `else` and `Color.parse` accepts it ([`L552-L559`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/style.py#L552-L559)). The trace shows the constructor turning it into `Color('red', ColorType.STANDARD, number=1)` ([`L155-L158`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/style.py#L155-L158)) — the 8-colour ANSI red, index 1, not a 24-bit triplet. The attribute flags become two integer bitmasks, `_set_attributes` recording *which* attributes were mentioned and `_attributes` recording their values ([`L160-L197`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/style.py#L160-L197)), which is what makes "bold is off" distinguishable from "bold was never set".

Back in `get_style`, the last line decides whether to hand out the cached object or a copy: `style.copy() if style.link else style` ([`L1492`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1492)). The trace duly checks `Style.link` ([`style.py#L457-L460`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/style.py#L457-L460)) and gets `None`, so the caller receives the very object `Style.parse` cached — `parse` is wrapped in `lru_cache(maxsize=4096)` ([`L496-L498`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/style.py#L496-L498)). Sharing is safe because `Style` is slotted and has no setters ([`L75-L87`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/style.py#L75-L87)); styles that carry a hyperlink are the exception, because each use needs a fresh `_link_id`.

> **For the owner:** A style name that does not parse is a hard failure at print time, not a silent fallback to plain text: `StyleSyntaxError` from `parse` becomes `errors.MissingStyle` ([`console.py#L1493-L1498`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1493-L1498)) and propagates out of `print`. That is usually what you want for a typo in your own source, but it means a style string built from configuration or user input can take down a logging call. Pass `default=` to `get_style` when the style name is not a literal you control.

The two answers are in hand: a `ConsoleOptions` describing a hundred-cell, non-terminal, UTF-8 world, and a `Style` carrying red and bold. The `Text` has not moved yet.

> **Leaves as:** `ConsoleOptions(size=ConsoleDimensions(100, 25), legacy_windows=False, min_width=1, max_width=100, is_terminal=False, encoding='utf-8', max_height=25, justify=None, overflow=None, no_wrap=None, highlight=None, markup=None, height=None)` and `Style(color=Color('red', ColorType.STANDARD, number=1), bold=True)`
