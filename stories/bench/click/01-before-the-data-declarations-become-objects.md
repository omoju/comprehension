# Chapter 1 · Before the data: declarations become objects

> **Enters as:** a plain function `hello(count, name)` and two sets of decorator keywords — `("--count", default=1, help="Number of greetings.")` and `("--name", prompt="Your name", help="The person to greet.")`

Nothing has been typed yet. There is no `--count=3`, no keystroke `Click\n`, no exit code. What exists at this moment is a function that takes two ordinary Python arguments and knows nothing about argv, and three decorator expressions sitting above it. Those expressions run at import time, in source order: `click.command()` first, then `click.option("--count", ...)`, then `click.option("--name", ...)`. Each one only manufactures a closure and hands it back — [`option` picks `Option` as its class and returns an inner `decorator`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/decorators.py#L370-L377), nothing more.

The real work starts when those closures are *applied*, and Python applies decorators bottom-up. So the first declaration to become an object is the one written last: `--name`.

## `--name` becomes an Option

[`decorator(f)` constructs `cls(param_decls, **attrs)` immediately](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/decorators.py#L373-L375), so `Option.__init__` runs with `param_decls=('--name',)`, `prompt='Your name'`, `help='The person to greet.'`, and — importantly — `flag_value=Sentinel.UNSET`, the default for an argument the caller never passed.

It delegates first [to `Parameter.__init__`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L3076-L3083), where three things are decided about the declaration.

**A name.** [`_parse_decls` walks the declarations](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L3364-L3389), splitting `'--name'` with [`_split_opt`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/parser.py#L111-L117) into the prefix `'--'` and the body `'name'`. With no explicit identifier among the declarations, [the longest spelling wins and is lowercased with dashes turned into underscores](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L3391-L3393). The result is the triple `('name', ['--name'], [])`: the Python name, the primary spellings, and no secondary (negating) spellings. That `name` is the keyword the function will eventually be called with, which is why [`_check_name_is_usable`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L2482-L2517) inspects it on the way past.

> **For the owner:** A declaration like `--from` or `--0-file` produces a parameter name that no Python callback can declare, and Click reports this as a `DeprecationWarning` today and [promises a `TypeError` in 9.0](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L2509-L2517). Run your test suite with deprecation warnings turned into errors so these surface before the upgrade.

**A type.** No `type=` was given, so [`convert_type(None, default)` is asked to guess](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L2389) from the default — and the default here is the sentinel `UNSET`. [`_guess_type` dutifully returns `type(UNSET)`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/types.py#L1321-L1328), the `Sentinel` enum class, which is exactly the sort of nonsense you do not want to become a converter. It does not: because the type was *guessed* rather than declared, [`convert_type` falls back to `STRING`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/types.py#L1372-L1385) rather than wrapping the enum in a `FuncParamType`. `--name` will therefore accept text.

**A default that is honestly absent.** [`self.default = default` keeps the raw sentinel](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L2404-L2410), and alongside it `self._default_explicit = default is not UNSET` records `False`. This pair is the whole reason Click can later tell "the author supplied no default" apart from "the author supplied `None`" — a distinction that matters when two options share a storage name, and again when a flag's default has to be derived lazily.

Back in `Option.__init__`, the remaining phases are quick. The prompt string is stored as given, `'Your name'`, and `prompt_required` stays `True`. [`_infer_flag_kind(is_flag=None, flag_value=UNSET)`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L3155-L3186) returns `(False, False)`: there is no `flag_value`, no secondary spelling, and `prompt_required` is on, so this is an ordinary value-taking option, not a flag. [`_pick_type`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L3202-L3209) sees a non-flag, non-count option and leaves `STRING` in place. Finally [`_validate`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L3251-L3271) checks the combinations that cannot work — `nargs=-1` on an option, a secondary spelling on a non-boolean flag, `count` together with `multiple` — and passes.

> **For the owner:** Every one of those illegal-combination checks sits behind [`if not __debug__: return`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L3257-L3258), so running the interpreter with `-O` constructs the broken option silently. Keep assertions enabled wherever the CLI is built, or treat a clean start under `-O` as unverified.

The finished object is then [appended to `f.__click_params__`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/decorators.py#L314-L321) — a list bolted onto the still-undecorated function, because there is no command yet to attach it to.

## `--count` takes the same road to a different place

The second decorator runs the identical path with one keyword changed: `default=1`. That single difference propagates. `_guess_type` sees an `int` and [`convert_type` returns the `INT` singleton](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/types.py#L1375-L1376); `_default_explicit` records `True`. `--count` is now an option that will insist on integers, purely because its default happened to be one.

> **For the owner:** An option's type is inferred from its default value, so changing a default from `1` to `None` silently changes the option from integer-parsing to text-parsing. Set `type=` explicitly on any option whose default is not representative of the values you expect.

## The command assembles itself

Last, the `command` closure receives the function. It [pops `__click_params__`, deletes the attribute, and extends its parameter list with `reversed(decorator_params)`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/decorators.py#L221-L230) — the reversal undoing the bottom-up application, so the options end up in the order a reader of the source would expect: `count`, then `name`. [The help text is taken from `f.__doc__`](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/decorators.py#L232-L233), and [the command name is the function name lowercased with underscores turned into dashes](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/decorators.py#L239-L246) — `hello`, with no `_command`/`_cmd`/`_group`/`_grp` suffix to strip. Then [`Command.__init__` stores name, callback, params and help](https://github.com/pallets/click/blob/06b2a678741131fd577ce170e23e5ca0aeba0309/src/click/core.py#L1080-L1095) and the module-level name `hello` stops being a function and becomes a `Command`.

> **For the owner:** The function's docstring is published verbatim as the program's `--help` body. Review docstrings on command callbacks as user-facing copy, not as internal notes.

Two options now stand ready: one that knows it wants an integer and has a fallback of `1`, one that knows it wants text, has no fallback at all, and carries a question to ask if nobody answers it. Neither has seen a single character of input.

> **Leaves as:** `<Command hello>` with `params == [<Option count>, <Option name>]`, where `count` has `type is INT`, `default == 1`, `_default_explicit is True`, and `name` has `type is STRING`, `default is UNSET`, `_default_explicit is False`, `prompt == 'Your name'`, `is_flag is False`
