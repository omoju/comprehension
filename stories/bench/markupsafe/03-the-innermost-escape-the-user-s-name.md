# Chapter 3 · The Innermost Escape: the user's name

> **Enters as:** `'Alice "The <b>Great</b>"'` — a plain `str`, handed as the sole argument to `Markup('<span class="user">{0}</span>').format(...)`

The name is the deepest point of the run. Everything above it — two template literals, a format spec, a half-built anchor tag — is waiting on this one string to come back inert.

`Markup.format` runs the same two lines it ran one level up ([`__init__.py#L313-L315`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L313-L315)): a fresh `EscapeFormatter` holding `Markup.escape` ([`__init__.py#L335-L337`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L335-L337)), then `vformat` to do the parsing. `vformat` locates the single field `{0}`, pulls the name out of the positional arguments, and calls `format_field(value='Alice "The <b>Great</b>"', format_spec='')`.

## The third door, this time

In `format_field` the first two doors are shut. A plain `str` has no `__html_format__` and no `__html__`, so the dispatch falls through to Python's ordinary formatting ([`__init__.py#L350-L353`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L350-L353)): `super().format_field(value, str(''))`, which with an empty spec returns the string unchanged. Only then does the escaping happen, on the last line of the method ([`__init__.py#L354`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L354)).

The order matters more than it looks. Escaping is applied to the *rendered* field, not to the value that arrived. That is why a `float` formatted with `%`-free `{:.2f}`, a date, a custom `__format__` — anything Python's machinery can turn into text — gets escaped too, rather than only the values that happened to start life as strings ([`tests/test_markupsafe.py#L169-L174`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/tests/test_markupsafe.py#L169-L174)).

`self.escape` here is `Markup.escape`, the classmethod ([`__init__.py#L230-L240`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L230-L240)); it forwards to the module-level `escape`, which takes the exact-`str` fast path it took in chapter 1 ([`__init__.py#L39-L40`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L39-L40)) and runs the five replacements ([`_native.py#L1-L8`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/_native.py#L1-L8)). The name comes back as `Markup('Alice &#34;The &lt;b&gt;Great&lt;/b&gt;&#34;')`: the two double quotes became `&#34;`, the `<b>` and `</b>` became `&lt;b&gt;` and `&lt;/b&gt;`.

Then `format_field` does something that looks like a step backwards: `str(...)` around the result. What it returns to `vformat`, as the trace records at this depth, is the bare `str` `'Alice &#34;The &lt;b&gt;Great&lt;/b&gt;&#34;'` — escaped text, but no longer carrying the safe type. That is deliberate. `string.Formatter.vformat` assembles its output with plain string concatenation; handing it `Markup` pieces would buy nothing, and the type is restored in one place at the end instead of being threaded through the standard library.

> **For the owner:** The double quote is the character to notice. MarkupSafe escapes both `"` and `'`, which is what makes an escaped value safe to drop inside a quoted HTML attribute — `title="{name}"` cannot be broken out of. It does *not* escape backtick, `=`, or whitespace, so an **unquoted** attribute (`title={name}`) is not protected: a space ends the value and the attacker is writing new attributes. If you are reviewing templates, "are all attribute values quoted?" is the assumption this escape set is built on. Likewise, nothing here helps inside a `<script>` or `<style>` block, or in a JavaScript string literal — those are different grammars with different escapes, and are out of scope.

## Back up one level, and then one more

`vformat` joins the trusted literal pieces of `<span class="user">{0}</span>` with that escaped field, and `Markup.format` wraps the joined string in `self.__class__(...)` — the no-op constructor ([`__init__.py#L122-L131`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L122-L131)) applied to text the library itself just assembled. `Markup('<span class="user">Alice &#34;The &lt;b&gt;Great&lt;/b&gt;&#34;</span>')` leaves `User.__html__`. That final wrap is where the safe type is reinstated; it is the same line that will reinstate it for the outer page later.

With both arguments now in hand — the integer `3` and that span — the anchor render runs: `Markup('<a href="/user/{}">{}</a>').format(3, span)`. The trace elides it as one more `Markup.format` at the same depth, because it is the path just told, twice over. The `3` has neither HTML method, so it goes the way the name went: `format(3, '')` gives `'3'`, and escaping `'3'` leaves `'3'`. The span goes a different way — `Markup` defines `__html_format__`, so it takes the *first* door, and `Markup.__html_format__('')` returns `self` unchanged because the spec is empty ([`__init__.py#L325-L329`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L325-L329)). Its tags survive verbatim; the escaped name inside them is not escaped again.

> **For the owner:** `3` is a database id here, and it lands in `href="/user/3"`. Escaping made it safe as *text inside a quoted attribute* and nothing more — it is not URL validation. If a value interpolated into an `href` or `src` can ever be attacker-influenced in full (a stored profile URL, a redirect target), `javascript:alert(1)` contains none of the five escaped characters and would pass through untouched. URL-scheme allow-listing is a separate control that this library does not claim to provide.

The anchor closes: `Markup('<a href="/user/3"><span class="user">Alice &#34;The &lt;b&gt;Great&lt;/b&gt;&#34;</span></a>')`. It is a `Markup`, it is already escaped exactly where it needs to be, and it is about to be handed back to `format_field` one level up — which will route it straight into `Markup.escape` again. Whether that second trip leaves the anchor tags alive or turns them into visible text is the next chapter's question.

> **Leaves as:** `Markup('<span class="user">Alice &#34;The &lt;b&gt;Great&lt;/b&gt;&#34;</span>')`, and then the completed `Markup('<a href="/user/3"><span class="user">Alice &#34;The &lt;b&gt;Great&lt;/b&gt;&#34;</span></a>')` returning from `User.__html_format__`
