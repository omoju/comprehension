# Chapter 7 · Deciding the Shape: Column Measurement and Collapse

> **Enters as:** the assembled `Table` (4 columns, 3 rows of raw strings) handed to `console.print(table)`, measured against `ConsoleOptions(max_width=100)`

The table has structure but no dimensions. Before a single box character can be drawn, somebody has to decide how wide each of the four columns gets to be — and the only budget available is the 100 cells the console was pinned to in Chapter 1.

## Recognised, not converted

`print` opens the buffer context and hands its one object to `_collect_renderables` ([`console.py#L1705-L1713`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1705-L1713)). The table makes the same first stop every object makes: `rich_cast`, which returns it unchanged because a `Table` has no `__rich__` ([`protocol.py#L18-L41`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/protocol.py#L18-L41)).

Then the chain of `isinstance` checks ([`console.py#L1556-L1579`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1556-L1579)). It is not a `str`, not a `Text`, but it *is* a `ConsoleRenderable` — a `runtime_checkable` Protocol whose entire test is "does this object have a `__rich_console__` attribute" ([`console.py#L256-L263`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L256-L263)). So the table is appended as-is ([`L1570-L1572`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1570-L1572)): no pretty-printing, no highlighting, no `Text` conversion. `check_text()` runs twice and does nothing both times, because no strings accumulated. The list that comes back is `[<rich.table.Table object>]`.

`Console.options` is rebuilt from scratch — `size` → `ConsoleDimensions(width=100, height=25)`, `encoding` → `'utf-8'`, `is_terminal` → `False` — and `update()` copies it with every override still `None` ([`console.py#L1716-L1724`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1716-L1724)). `Console.render` casts again, resets `height` ([`L1338`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1338)), confirms the object has `__rich_console__` and is not itself a class ([`L1318-L1319`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1318-L1319)), and calls it. The guard at the top — return immediately if `max_width < 1` ([`L1312-L1314`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L1312-L1314)) — is what stops a nested renderable from recursing forever on zero width; at 100 it is a no-op.

## The budget

`Table.__rich_console__` begins with arithmetic ([`table.py#L482-L491`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L482-L491)). `self.width` is `None`, so `max_width` stays 100. Then `_extra_width` ([`L295-L303`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L295-L303)) counts what the frame will cost before any content exists: two cells for the outer edges, plus one per divider between four columns — `2 + 3`, and the trace shows `→ 5`.

95 cells of content budget, handed down as `options.update_width(95)` ([`L488-L490`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L488-L490)). `update_width` clamps with `max(0, width)` ([`console.py#L194-L205`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/console.py#L194-L205)), so a console narrower than the frame yields a budget of zero rather than a negative one.

## Measuring four columns

`_calculate_column_widths` measures every column, then decides whether the result fits ([`table.py#L523-L586`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L523-L586)).

The Date column takes the short path. `_get_padding_width(0)` reads the normalised `(0, 1, 0, 1)` and returns `pad_left + pad_right` = 2 ([`L700-L714`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L700-L714)); because `column.width` is 12, `_measure_column` returns a fixed `Measurement(12 + 2, 12 + 2)` and clamps it against the budget ([`L729-L733`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L729-L733)). The trace: `with_maximum(95) → Measurement(minimum=14, maximum=14)`. The cells are never looked at.

The other three have `width=None`, so they are measured from their contents ([`L734-L748`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L734-L748)). `_get_cells` yields header, body cells and footer, each already wrapped in a `Padding` ([`L684-L691`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L684-L691)), and `Measurement.get` is asked for each one. For a padded string, that routes through `Padding.__rich_measure__`, which adds `left + right` to whatever is inside ([`padding.py#L125-L135`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/padding.py#L125-L135)) — which is why the fixed column adds its 2 by hand and the flexible ones do not.

The inner string reaches `Measurement.get`, which converts it with `console.render_str(renderable, markup=options.markup, highlight=False)` ([`measure.py#L98-L101`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/measure.py#L98-L101)). Two consequences worth naming. Markup is honoured, so `'[red]Solo[/red]: A Star Wars Story'` is measured as the 23 visible cells of `Solo: A Star Wars Story` — tags cost nothing. And highlighting is forced off, so measurement can never disagree with rendering about width on account of a regex.

The column finally reports `max(min_widths)` and `max(max_widths)` across its cells, clamped to the budget and then to the column's own `min_width`/`max_width` ([`L745-L752`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L745-L752)). The maxima are taken as the working widths, with `or 1` so a column measuring zero still occupies a cell ([`L532`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L532)). The trace reports the answer: `[14, 35, 19, 16]`. Those numbers are the widest cell in each column plus two of padding — 35 is `Star Wars Ep. VIII: The Last Jedi`, 19 is the header `Production Budget`, 16 is `$1,332,539,889` (inference from the arithmetic; the trace folds the three flexible measurements).

> **For the owner:** Measurement renders the cell contents a second time — once to measure, once to draw — and a third time if the collapse path below triggers a re-measure ([`table.py#L569-L573`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L569-L573)). Keep `__rich_measure__` and `__rich_console__` free of side effects and cheap in any custom renderable you put in a cell, because Rich will call them more than once per `print`.

## Two roads not taken

`self.expand` is consulted twice and answers `False` both times ([`L285-L288`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L285-L288)) — no `width=` was set and `expand=False` was the default. So the ratio-distribution branch is skipped ([`L536-L553`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L536-L553)), and so is the pad-out branch at the end ([`L575-L584`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L575-L584)). The table will render at its natural size, narrower than the console.

The other skipped road is the one that matters when things go wrong. `sum(widths)` is 84, under the 95-cell budget, so `_collapse_widths` is never called ([`L556-L573`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L556-L573)). Had it been, it would have repeatedly shaved the widest column down toward the second widest — but only among columns marked shrinkable, which is `column.width is None and not column.no_wrap` ([`L557-L561`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L557-L561), [`L588-L625`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L588-L625)). The Date column, with its explicit `width=12`, would have been protected. And if that still did not fit, the last resort reduces *every* column evenly, protection or not ([`L563-L567`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L563-L567)).

> **For the owner:** An explicit `width=` or `no_wrap=True` on a column is a preference, not a contract. It holds while the table fits and while some other column can give way; under real pressure the even reduction shrinks fixed columns too, and the column's `overflow='ellipsis'` default then truncates the content with a `…`. If a column must never lose characters, bound the data or the console width yourself rather than relying on `width=`.

## What leaves

`table_width = sum(widths) + extra_width` = `84 + 5` = 89, and the options that will govern every cell are built from it ([`L493-L495`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L493-L495)): `width=89`, `height=None`, and `highlight=self.highlight` — `False`. The trace shows exactly that call. The console's automatic `ReprHighlighter`, which was on for `'Hello'` in Chapter 2, is switched off for everything inside this table; markup, however, is left alone and will be interpreted cell by cell in the next chapter.

`self.title` is `None`, so the annotation branch is skipped ([`L509-L514`](https://github.com/Textualize/rich/blob/9d8f9a372cc5916fd4781fec207ced7ddac2f08f/rich/table.py#L509-L514)) and control passes straight to `_render` with the four numbers.

> **Leaves as:** `widths = [14, 35, 19, 16]` (table width 89, inside the console's 100) and `ConsoleOptions(min_width=89, max_width=89, highlight=False, height=None)`
