# Chapter 9 · Patching In Place, and the Coda

> **Enters as:** a `_ClassBuilder(cls=C)` holding three unevaluated snippets plus a `_cls_dict` of `__attrs_attrs__`, `__attrs_props__`, `__ne__`, `__lt__`/`__le__`/`__gt__`/`__ge__`, `__hash__ = None`, `__replace__`, and `__match_args__ = ('a', 'b')`

[`build_class`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L800-L821) opens the same way it did for `SomeClass`: evaluate the snippets, then decide how to deliver the result. The decision is one line, and this time it goes the other way.

## One compile, three functions

[`_eval_snippets`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L782-L798) joins the repr, eq and init sources into a single string and merges their three globs dicts into one. [`_generate_unique_filename(C, "methods")`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1634-L1641) produces `<attrs generated methods __main__.C>`, and [`_linecache_and_compile`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L231-L263) files the source under that name in the interpreter's global `linecache.cache` — a four-tuple of length, `None` mtime, the split lines, and the filename — before handing it to [`compile()` and `eval()`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L227-L228). That cache entry is why a debugger can step into `C.__init__` and why a traceback through it shows real source lines.

This is also the `compile()` that chapter 7's unvalidated names would have reached. `make_class` normalizes the class name and otherwise trusts you; a field called `a-b` or `class` becomes a parameter name in the generated `def __init__(self, a-b, …)` and dies here as a `SyntaxError`, far from the call that caused it.

The `eval` is given `globs` and a separate empty `locs`, so the three `def` statements bind into `locs` — the trace shows it coming back as `{'__eq__': …, '__init__': …, '__repr__': …}` — while each function's `__globals__` is the merged `globs` dict, the one carrying `Factory`, `NOTHING`, `SomeClass` and the rest of the defining module's namespace snapshot. The three attach hooks then run in registration order, each fishing its function out of that shared dict and passing it through [`_add_method_dunders_unsafe`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1226-L1238), which mutates the function in place: `__module__`, `__qualname__` (`C.__repr__`, `C.__eq__`, `C.__init__`) and a generated docstring. You can see the mutation propagate in the trace — by the time [`_attach_eq`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1155-L1156) is called, the `__repr__` in the dict it is handed already reads `<function C.__repr__>`.

> **For the owner:** Each distinct generated source gets a permanent entry in the process-wide `linecache.cache`, and *attrs* never removes it; repeated calls with the same filename but different source append a `-1`, `-2` suffix and add another entry. Check that you are not building *attrs* classes dynamically in a long-running loop, and call `linecache.clearcache()` if you must.

## The class you handed in is the class you get back

`self._slots` is `False`, so [`build_class`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L806-L811) skips `_create_slots_class` entirely and calls `abc.update_abstractmethods(self._patch_original_class())`. Everything chapter 5 had to warn about — the identity swap, the `__attrs_base_of_slotted__` weak reference, the closure-cell rewriting for bare `super()`, the double `__init_subclass__` fire, the dead original lingering in `type.__subclasses__` — simply does not happen here. There is no second class.

[`_patch_original_class`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L823-L857) does three things and returns the object it was given. First it checks `self._delete_attribs`, which chapter 8 saw set to `False` because fields arrived via `these`; so [the loop that normally strips `attr.ib()` sentinels off the class body](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L831-L841) is skipped. Second, it [`setattr`s every entry of `_cls_dict` onto the class](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L843-L845) — the compiled trio, the four ordering closures, `__ne__`, `__hash__ = None`, `__replace__`, `__match_args__`, `__attrs_attrs__`, `__attrs_props__`. Third, it checks whether the class *inherited* an attrs-written `__setattr__` while writing none of its own; [that branch](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L849-L855) resets `__attrs_own_setattr__` and restores `object.__setattr__`, and it is the only place in the library where an inherited hook is taken *away*. `C`'s only base is `object`, so it does nothing.

`abc.update_abstractmethods` then recomputes `__abstractmethods__`, which matters because a patched class may have just acquired implementations of abstract methods that were missing when `type` first evaluated it. Finally [`build_class` looks for an inherited `__attrs_init_subclass__`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L813-L819) — *attrs*' replacement for the `__init_subclass__` hook that slotted classes break — finds none, and returns `<class '__main__.C'>`.

> **For the owner:** For non-slotted classes the decorator mutates and returns the same class object, so any reference captured before it ran still points at the finished class; for slotted classes (the `define` default) it does not, and a pre-decoration reference points at a dead class. Treat `@define` as returning a new object and never capture the undecorated class.

> **For the owner:** The in-place patch overwrites same-named attributes without warning, and `attr.s` / `make_class` leave `auto_detect` at `False`, so a hand-written `__repr__` or `__eq__` on a class decorated with `@attr.s` is silently replaced by the generated one. Use `@attrs.define`, which sets `auto_detect=True`, or pass the relevant flag as `False` explicitly.

## The coda

Control returns to [`make_class`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L3356-L3361), which attaches annotations only now — deliberately, because doing it earlier would have made `_transform_attrs` treat them as `auto_attribs` fields. Both `_CountingAttr`s have `type=None`, so `C.__annotations__` becomes `{}`.

`C("foo", "bar")` then runs the two-line initializer into an ordinary instance `__dict__`, and `repr(made)` returns `C(a='foo', b='bar')` from the generated function. Neither call appears in the trace, because neither is library code any more.

The last entry is the one the scenario's final assertion triggers: [`__ne__`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1730-L1739), the single shared function that every *attrs* class points at. It calls `sc.__eq__(SomeClass(2, [3, 2, 1]))`; the generated `__eq__` confirms both operands are exactly `SomeClass`, compares `1 == 2`, short-circuits the `and` chain and returns `False`; `__ne__` sees a real boolean rather than `NotImplemented` and returns `True`.

That is the whole runtime footprint. Across two classes, one instance built, compared twice, repr'd, serialized and a second class conjured from two strings, the only *attrs* functions that executed after class creation were `__ne__` and the `asdict` helper the caller asked for by name. Every other guarantee in this run — the signature, the defaults, the fresh list per instance, the type-exact equality, the unhashability, the field list — was compiled into the class at import time and then got out of the way.

> **Leaves as:** `<class '__main__.C'>` — the same object `types.new_class` produced, now carrying `__init__`, `__repr__`, `__eq__`, `__ne__`, four ordering methods, `__hash__ = None`, `__replace__`, `__match_args__ = ('a', 'b')`, `__attrs_attrs__`, `__attrs_props__` and `__annotations__ = {}`; `C("foo", "bar")` reprs as `C(a='foo', b='bar')`, and `sc.__ne__(SomeClass(2, [3, 2, 1]))` → `True`
