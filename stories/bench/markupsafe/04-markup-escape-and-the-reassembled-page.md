# Chapter 4 · Markup.escape and the Reassembled Page

> **Enters as:** `s = Markup('<a href="/user/3"><span class="user">Alice &#34;The &lt;b&gt;Great&lt;/b&gt;&#34;</span></a>')`, arriving at `Markup.escape` from the last line of `format_field`

The anchor has come back out of `User.__html_format__` and is now the local `rv` inside `EscapeFormatter.format_field`. The method has one line left: `return str(self.escape(rv))` ([`__init__.py#L354`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L354)). Every branch of the dispatch — the `__html_format__` door, the `__html__` door, the default door — funnels through this same escape call. That is the point of the design: there is one exit, and nothing leaves a format field without passing it.

So the anchor, tags and all, is handed to the escaper.

## A second trip that changes nothing

`self.escape` is `Markup.escape`, the classmethod ([`__init__.py#L230-L240`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L230-L240)). It calls the module-level `escape` and inspects what comes back.

Inside `escape`, the anchor fails the exact-type test — `type(s) is str` is false for a `Markup`, which is a *subclass* of `str` ([`__init__.py#L39`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L39)) — and falls to the `__html__` branch ([`__init__.py#L42-L43`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L42-L43)). `Markup.__html__` returns `self` ([`__init__.py#L133-L134`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L133-L134)), and the result is passed to `Markup(...)`, whose constructor checks for `__html__` once more and calls it a second time ([`__init__.py#L125-L126`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L125-L126)) — the trace shows both calls, at depth and again one level in. For a `Markup` that is cheap. For a user-written `__html__` that queries a database or builds a fragment, it is two invocations per `escape` call; worth knowing if yours has a cost or a side effect.

What `Markup(...)` produces here is a *fresh* `Markup` carrying the same characters: no replacement ran, but `str.__new__` on a subclass still allocates ([`__init__.py#L128-L129`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L128-L129)). Back in `Markup.escape`, that value's class is compared with `cls`: `rv.__class__ is not cls` is false, so `escape`'s result is returned as-is instead of being pushed through `cls(...)` a second time ([`__init__.py#L237-L240`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L237-L240)) — one wrap saved on a path that runs once per format field. That comparison is also what makes `Markup` subclassable: because the module-level `escape` always builds a plain `Markup` ([`__init__.py#L43`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L43)), an application's `class MyMarkup(Markup)` would otherwise be quietly downgraded on every escape; the re-wrap puts the subclass back, so escaping, formatting, joining and concatenation all return the application's own type.

The anchor therefore reaches `str(...)` with its text unchanged, and `format_field` returns the bare string `'<a href="/user/3"><span class="user">Alice &#34;The &lt;b&gt;Great&lt;/b&gt;&#34;</span></a>'`. The tags are alive. The name inside them is still escaped, exactly once.

> **For the owner:** This is the trust boundary in its most concrete form. The anchor was built by MarkupSafe's own formatter, so its tags are there by construction — but `escape` cannot tell that apart from an `__html__` that pasted raw request data between two angle brackets. Whatever an `__html__`/`__html_format__` returns as `Markup` is inserted verbatim, here and anywhere else. When reviewing, the question is not "does the template escape?" (it does) but "does every `__html__` in our codebase build its output through `Markup(...).format` or `escape`, rather than f-strings over user data?" One careless `__html__` defeats everything downstream of it. The mirror image is a quieter surprise in your favour: if `__html_format__` returns a *plain* `str` containing tags, this line escapes it and the tags show up as visible text rather than markup ([`docs/formatting.rst#L17-L19`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/docs/formatting.rst#L17-L19)).

## The second field, and the join

`vformat` moves on to `{comment}`. The trace elides it — `EscapeFormatter.format_field ×1 more` — because it is the path just walked. The value is `Markup('&lt;script&gt;alert(document.cookie);&lt;/script&gt;')`, the escaped comment from chapter 1. Being a `Markup`, it takes the first door, `__html_format__`, which returns `self` for an empty spec ([`__init__.py#L325-L329`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L325-L329)), and then the same `escape` round trip leaves its text untouched. Its `&lt;script&gt;` is not escaped into `&amp;lt;script&amp;gt;`; the comment is rendered once and only once, no matter how many `Markup` layers it passes through.

`string.Formatter.vformat` now concatenates the trusted literal pieces of the template — `'<p>User: '`, `' said: '`, `'</p>'` — with those two plain strings, and `Markup.format` wraps the whole joined result in `self.__class__(...)` ([`__init__.py#L313-L315`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L313-L315)). The trace records that final constructor call with the complete page text. This single wrap is where the safe type is restored, after the standard library has done its plain-string work; the bare `str`s in between were never visible outside the formatter.

The page leaves as `Markup('<p>User: <a href="/user/3"><span class="user">Alice &#34;The &lt;b&gt;Great&lt;/b&gt;&#34;</span></a> said: &lt;script&gt;alert(document.cookie);&lt;/script&gt;</p>')`, and `print(repr(page))` sends it through `Markup.__repr__` ([`__init__.py#L167-L168`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L167-L168)), which prefixes the class name so a safe value is distinguishable from a plain string in a log or a REPL. The scenario's `assert "<script>" not in page` holds — not because anything inspected the output, but because the only route the comment could take escaped it before it ever reached the join.

> **For the owner:** Formatting fails loudly, which is the behaviour you want at a boundary. A misspelled field name raises `KeyError` out of `string.Formatter`; a format spec on an object that defines `__html__` but not `__html_format__` raises `ValueError` naming the type ([`__init__.py#L343-L348`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L343-L348)); the `%` path raises `TypeError` on a missing argument ([`tests/test_markupsafe.py#L55-L58`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/tests/test_markupsafe.py#L55-L58)). There is no "render what we can and drop the rest" mode, so a template bug surfaces as a 500, not as a half-escaped page. The one thing this chapter does *not* protect is the template itself: `Markup("<p>…{x}…")` trusts its literal text completely. If a template string is ever assembled from user input before `.format()` is called, nothing here will save you.
