# Chapter 2 · An Object That Writes Its Own HTML, and a Template That Escapes Its Arguments

> **Enters as:** a `User` instance with `id=3` and `name='Alice "The <b>Great</b>"'`, with `Markup('&lt;script&gt;alert(document.cookie);&lt;/script&gt;')` waiting beside it

The escaped comment now waits. The scenario built a second value for the same page: a `User` object that knows how to write its own HTML. The scenario handed that object to `escape`. This time the first test, `type(s) is str`, fails, because a `User` is not a `str`. The second test, `hasattr(s, "__html__")`, succeeds, so `escape` calls the method and wraps the result ([`__init__.py:42-43`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L42-L43)). The trace collapses the nested calls into one line; chapter 3 shows the same work in full.

`escape` does not escape the text that `__html__` returns. It marks it safe without a check. This `User` is careful: its `__html__` builds the span with `Markup('<span class="user">{0}</span>').format(self.name)`, so the name goes through the escape machinery. The library cannot verify that an arbitrary `__html__` did the same. The documentation states this responsibility in plain words ([`docs/html.rst:31-43`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/docs/html.rst#L31-L43)). The result of the call was `Markup('<span class="user">Alice &#34;The &lt;b&gt;Great&lt;/b&gt;&#34;</span>')`: the tags live, the name inert.

> **For the owner:** This is the second unguarded door, after `Markup(text)` from chapter 1. Every `__html__` and `__html_format__` method in your codebase is part of the trust boundary. The library believes the text that these methods return. Review each one, and check that it escapes the data it inserts.

`escape` puts no `try` block around the call to `__html__` ([`__init__.py:42-45`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L42-L45)). An exception from that method therefore leaves `escape` unchanged. The C path once lost such an exception and crashed; a test now pins the behaviour ([`tests/test_exception_custom_html.py:13-23`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/tests/test_exception_custom_html.py#L13-L23)). The scenario printed the user markup through `Markup.__repr__`, which returned `'Markup(\'<span class="user">Alice &#3...lt;b&gt;Great&lt;/b&gt;&#34;</span>\')'` in the trace, truncated for width.

Next the template arrived. `Markup.__new__` received the literal `'<p>User: {user:link} said: {comment}</p>'` with `encoding=None`, and returned `Markup('<p>User: {user:link} said: {comment}</p>')` ([`__init__.py:122-131`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L122-L131)). The template text is trusted because a developer wrote it in the source file. Only the substituted values get escaped. The escaped comment and the `User` object both travel in as keyword arguments.

> **For the owner:** The safety of `Markup.format` depends on the template, not only on the arguments. A template built from user input gives the user control over tags and attributes, and nothing in this module stops that. Require all `Markup` templates to be literals or developer-controlled text.

`Markup.format` starts the render. It creates one `EscapeFormatter` and passes `self.escape`, the bound classmethod of the actual class ([`__init__.py:313-315`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L313-L315)). `EscapeFormatter.__init__` stores that callable and calls `string.Formatter.__init__` ([`__init__.py:335-337`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L335-L337)). The trace shows the return value `None`. Each call builds a new formatter, so two renders share no mutable state. Parsing of `{user:link}` and `{comment}` belongs to `string.Formatter.vformat` in the standard library; only field rendering is custom. `format_map` uses the same machinery with an empty `args` tuple ([`__init__.py:317-323`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L317-L323)).

`vformat` reached the first field and called `EscapeFormatter.format_field` with `value=<User object>` and `format_spec='link'`. The method tests three things in a fixed order ([`__init__.py:339-354`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L339-L354)). It tests `__html_format__` first ([`__init__.py:340-341`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L340-L341)). The `User` has that method, so it wins, and it receives the raw string `'link'`. MarkupSafe defines no grammar for the specifier; the class decides what `'link'` means. All three tests use `hasattr`, so any object that declares these method names is believed.

Two roads lead away from here, and this field took neither. An object with `__html__` but without `__html_format__`, combined with a non-empty specifier, causes a `ValueError` that names the type ([`__init__.py:342-348`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L342-L348)). A specifier is therefore never dropped in silence. `Markup.__html_format__` raises the same kind of error for any non-empty specifier, so `{0:>10}` on a `Markup` is an error and not padding ([`__init__.py:325-329`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L325-L329)). The third road is the `%` operator, which wraps each argument in `_MarkupEscapeHelper` and escapes it late, inside `__str__` ([`__init__.py:154-165`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L154-L165), [`__init__.py:366-379`](https://github.com/pallets/markupsafe/blob/b2e4d9c7687be25695fffbe93a37622302b24fb1/src/markupsafe/__init__.py#L366-L379)).

Control is now inside `User.__html_format__`, in the scenario's own code. The method built `Markup('<a href="/user/{}">{}</a>')` through the same unguarded constructor, with a developer-written literal. It then evaluated the arguments for the inner render. The second argument is `self.__html__()`, which built `Markup('<span class="user">{0}</span>')` and is about to format the name into it.

> **Leaves as:** control inside `User.__html_format__`, holding `Markup('<a href="/user/{}">{}</a>')` and the just-built `Markup('<span class="user">{0}</span>')`
