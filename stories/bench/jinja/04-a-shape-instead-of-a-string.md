# Chapter 4 · A Shape Instead Of A String

> **Enters as:** a `TokenStream` over `members.html`, current token `Token(lineno=1, type='block_begin', value='{%')`, on a `Parser` with no extension tags

`Parser.parse` is three lines: call `subparse()`, wrap whatever comes back in a `nodes.Template`, attach the environment ([parser.py#L1037-L1041](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/parser.py#L1037-L1041)). Everything interesting is in the first of those.

`subparse` sets up two lists. `body` is the result; `data_buffer` is a holding pen for literal text and interpolations, which get flushed into a single `Output` node whenever a `{% %}` tag interrupts them ([parser.py#L991-L1002](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/parser.py#L991-L1002)). Called with `end_tokens=None`, it pushes nothing onto `_end_token_stack` — that stack exists only so that a premature end-of-template can say which tag it was still waiting for ([parser.py#L995-L996](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/parser.py#L995-L996), [parser.py#L99-L120](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/parser.py#L99-L120)).

Then the loop, and the loop recognises exactly three things ([parser.py#L1005-L1029](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/parser.py#L1005-L1029)): a `data` token, a `variable_begin`, a `block_begin`. Anything else is an internal bug and raises `AssertionError`. The whole template language, from the parser's seat, is text, `{{ … }}`, and `{% … %}`.

The first token is `block_begin`. `flush_data` runs first and finds the buffer empty, so it does nothing; `next(self.stream)` consumes the `{%` and moves `current` forward to `Token(lineno=1, type='name', value='extends')`. Now `parse_statement` is asked what kind of statement this is.

Its dispatch is deliberately narrow ([parser.py#L163-L187](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/parser.py#L163-L187)). The token must be a `name`, or it fails with "tag name expected". If the name is in `_statement_keywords` — a frozen set of twelve ([parser.py#L20-L35](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/parser.py#L20-L35)) — the parser calls `getattr(self, f"parse_{value}")`. `call` and `filter` get their own two lines. After that, the only remaining possibility is `self.extensions.get(token.value)`, the dict that chapter 3 left empty. Miss all of those and you get `fail_unknown_tag`, which raises a `TemplateSyntaxError` naming the tag and, if the parser was mid-block, the innermost block still waiting to be closed.

> **For the owner:** The set of tags a template may use is fixed at import time — built-ins plus whatever extensions the environment loaded. An unknown tag is a `TemplateSyntaxError` raised during compilation, not a silent no-op and not a render-time surprise ([parser.py#L178-L187](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/parser.py#L178-L187)). Templates cannot introduce new syntax; only your Python code can.

`extends` is in the keyword set, so `parse_extends` runs. It is four lines: take the lineno, parse one expression as the template name, return ([parser.py#L324-L327](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/parser.py#L324-L327)). The thirty-nine nested calls under it in the trace are the full expression grammar descending — condexpr, or, and, not, compare, math, concat, pow, unary — down to `parse_primary`, which sees a `string` token, joins any adjacent string literals, and builds `nodes.Const("base.html")` ([parser.py#L658-L665](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/parser.py#L658-L665)). The result is `Extends(template=Const(value='base.html'))`.

Worth holding onto: nothing in that node says "this file has been located". It is a constant string sitting in a tree. It happens to be constant here only because the template wrote a quoted literal; the same four lines of `parse_extends` would accept `{% extends some_variable %}` and store a `Name` node instead. Which of those two the parser built turns out to matter a great deal later.

Back in `subparse`, `expect('block_end')` consumes the `%}` ([parser.py#L1027](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/parser.py#L1027)), and `TokenStream.expect` is where a missing closing delimiter turns into a readable error carrying the lineno, name and filename ([lexer.py#L403-L425](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/lexer.py#L403-L425)).

The next token is `data` with value `'\n'` — the newline between the extends tag and the first block. It becomes `TemplateData('\n')` and goes into the buffer ([parser.py#L1007-L1010](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/parser.py#L1007-L1010)). `TemplateData` is a literal: it holds template text, and `as_const` on it returns that text, wrapped in `Markup` if autoescaping is on ([nodes.py#L608-L620](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/nodes.py#L608-L620)). Text from the template file is trusted; text from the context never travels this way.

The following `block_begin` triggers `flush_data`, which wraps the buffered node in `Output(nodes=[TemplateData('\n')], lineno=1)` and empties the pen ([parser.py#L998-L1002](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/parser.py#L998-L1002)). That stray newline is now a real statement in the tree, sitting at the top level of a template that extends another one. Keep an eye on it.

`parse_block` takes the title block ([parser.py#L292-L322](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/parser.py#L292-L322)). It reads the name via `expect("name")`, checks for the optional `scoped` and `required` markers (both absent, so both `False`), and — a small kindness — if the next token is a `sub` it stops and explains that Jinja block names cannot contain hyphens ([parser.py#L301-L305](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/parser.py#L301-L305)). Then `parse_statements(("name:endblock",), drop_needle=True)` recurses into `subparse` with an end-token this time, so the inner loop stops when it sees `endblock` and the needle is consumed ([parser.py#L192-L219](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/parser.py#L192-L219)). If the stream runs out first, `fail_eof` reports what it was looking for. Out comes `Block(name='title', body=[Output(nodes=[TemplateData('Members')])], scoped=False, required=False)`.

Another `'\n'`, another `Output`. Then the content block, and the two hundred and eighty nested calls under it are the only genuinely structured piece of this template. When the inner `subparse` meets `{% for %}` it dispatches to `parse_for`, which parses an assignment target, the `in` keyword, the iterable, and a body ([parser.py#L232-L249](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/parser.py#L232-L249)); when it meets `{{ user.url }}` it calls `parse_tuple`, whose postfix parser turns the dot into `Getattr(node=Name('user','load'), attr='url')` ([parser.py#L1011-L1014](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/parser.py#L1011-L1014), [parser.py#L805-L819](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/parser.py#L805-L819)). Because `flush_data` only fires on a block tag, the whole `<li>…</li>` line — text, expression, text, expression, text — ends up as a *single* `Output` node with five children. The trace confirms the shape a few hundred lines later, where the compiler is handed `[Output(nodes=[TemplateData(data='\n  <ul>\n  ')]), For(target=Name(name='user', ctx='stor…, else_=[], test=None, recursive=False), Output(nodes=[TemplateData(data='\n  </ul>\n')])]`.

The last `expect('block_end')` lands on line 9. `TokenStream.__bool__` now returns `False`, the loop exits, the final `flush_data` finds nothing left, and `subparse` returns five nodes: `Extends`, `Output`, `Block('title')`, `Output`, `Block('content')`.

`nodes.Template(body, lineno=1)` wraps them. `Node.__init__` is strict about arity and attributes — the wrong number of fields or an unknown keyword is a `TypeError` ([nodes.py#L129-L145](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/nodes.py#L129-L145)).

Then one last pass. `set_environment` walks the entire tree breadth-first with a deque and sets `node.environment = environment` on every node it reaches — fifty-one `iter_child_nodes` calls in the trace ([nodes.py#L231-L238](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/nodes.py#L231-L238)). This looks like bookkeeping and is not. An expression node asked for its constant value without being given an eval context will build one from its own `environment`, and refuse with a `RuntimeError` if it has none ([nodes.py#L94-L102](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/nodes.py#L94-L102)). The tree has just been given the keys to the environment's filters and tests.

> **For the owner:** That attachment is what allows the optimizer to evaluate constant expressions during compilation — including *calling your filter functions* with constant arguments and folding the result into the generated code ([nodes.py#L746-L780](https://github.com/pallets/jinja/blob/5ef70112a1ff19c05324ff889dd30405b1002044/src/jinja2/nodes.py#L746-L780)). Keep custom filters pure; a filter that writes to a database or reads a request will run at compile time, once, for `{{ "x"|myfilter }}`.

What leaves this chapter is a shape. No file has been opened for `base.html`; no variable named `users` has been looked for; `Tom & Jerry` does not exist anywhere yet. There is only a tree that says: this template extends a constant, defines two named holes, and has two stray newlines at the top level that nobody has yet decided what to do with.

> **Leaves as:** `Template(body=[Extends(template=Const(value='base.html')), Output(nodes=[TemplateData(data='\n')]), Block(name='title', …), Output(nodes=[TemplateData(data='\n')]), Block(name='content', …)])`, every node carrying `environment`
