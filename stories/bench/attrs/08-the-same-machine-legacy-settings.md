# Chapter 8 · The Same Machine, Legacy Settings

> **Enters as:** `attrs.<locals>.wrap(cls=<type C>)` — the bare class from `types.new_class`, with `these={'a': _CountingAttr(counter=8), 'b': _CountingAttr(counter=9)}`, `auto_attribs=False`, `collect_by_mro=False`, `slots=False`, `eq=True`, `order=True`, `force_kw_only=True` closed over it

The same `wrap` that processed `SomeClass` in chapter 1 opens again, and this time the class it receives is empty. No annotations, no methods, no defaults — the two field definitions are riding in the closure, in `these`, not in the class body. Everything downstream from here is the machinery of chapters 2 through 5 run a second time, with the dials turned to the positions `attr.s` left them in.

## Three questions, answered cheaply

[`_has_frozen_base_class(C)`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1626-L1631) compares `C.__setattr__` to `_frozen_setattrs` and gets `False`: `object` is the only base, so nothing immutable is inherited. Next, `auto_detect` is `False`, so [the custom-`__setattr__` probe](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1482-L1484) short-circuits on the `and` without ever calling `_has_own_attribute` — which is why the trace for `C` shows none of the `__eq__` / `__init__` / `__hash__` dictionary probes that cluttered chapter 1.

The same shortcut runs through every flag. [`_determine_whether_to_implement`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1339-L1344) returns the flag immediately when it is `True` or `False`, and returns `default` the moment it sees `flag is None and auto_detect is False`. It is called five times for `C` — eq, init, repr, ordering, pickling — and never looks at the class at all. `eq` and `order` were handed in as explicit `True`, so both come back `True`. `getstate_setstate` is `None` with a `default` of [`slots`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1553-L1559), which is `False` here: **this class gets no `__getstate__`/`__setstate__`**, unlike the slotted `SomeClass`, because a dict class pickles fine without them.

Hashability lands in the same place by a different route. With `hash is None` and `auto_detect` off, [the chain](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1506-L1518) skips the own-`__hash__` probe, finds `eq is True` but `is_frozen is False`, and falls to the final `else`: `UNHASHABLE`.

And despite `force_kw_only=True` arriving from `make_class`, [the keyword-only decision](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1523-L1527) is gated on `kw_only` being truthy first. It is `False`, so `kwo = KeywordOnly.NO` and the flag never fires.

> **For the owner:** `make_class` and `attr.s` default `force_kw_only` to `True`, while `define` defaults it to `False`. If you pass `kw_only=True` to `make_class`, every attribute becomes keyword-only including inherited ones and ones that set `kw_only=False` themselves; pass `force_kw_only=False` if you want the modern per-class behavior.

The result is [a `ClassProps`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1529-L1562) that reads as the mirror image of chapter 1's: `is_slotted=False`, `collected_fields_by_mro=False`, `added_ordering=True`, `added_pickling=False`, `on_setattr_hook=None`, `hashability=UNHASHABLE`. [`is_hashable`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L3056-L3061) returns `False`, so the `cache_hash` guard passes trivially.

## Harvesting fields that were never in the class

[`_ClassBuilder.__init__`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L684-L691) calls `_transform_attrs` as before, and this time [the very first branch](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L402-L403) takes over: `these is not None`, so `ca_list = list(these.items())` and the class body is never scanned. [`_get_annotations(C)`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_compat.py#L30-L34) still runs — the trace records it returning `{}` — but its only remaining job is supplying `anns.get(attr_name)` as the type, which is `None` for both fields.

Each `_CountingAttr` is frozen into an [`Attribute`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L2594-L2626): `Attribute(name='a', default=NOTHING, type=None, kw_only=False, eq=True, order=True, alias=None, alias_is_default=True)`, and the same for `b`. Because neither carries an explicit alias, [the alias-filling loop](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L471-L476) reaches past the frozen `__setattr__` with `object.__setattr__` and writes `alias='a'` and `alias='b'`. Both defaults are `NOTHING`, so [the mandatory-after-default ordering check](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L485-L489) never trips.

Between those two steps sits the one genuine divergence. `collect_by_mro` is `False`, so base-class fields are gathered by [`_collect_base_attrs_broken`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L353-L378) rather than the MRO-correct version chapter 2 used. Its own docstring says it "adhere[s] to the old incorrect behavior": it walks the MRO *forward* instead of reversed, it keeps attributes that were already marked `inherited`, and it mutates the `taken_attr_names` set it was given. For `C`, whose `__mro__[1:-1]` is empty, it returns `([], {})` and the choice is invisible. For any `make_class` class with an *attrs* base, it is not.

> **For the owner:** `make_class` leaves `collect_by_mro` at `attr.s`'s default of `False`, which reproduces the known-wrong field ordering of issue #428 when the new class inherits from other *attrs* classes. Pass `collect_by_mro=True` to `make_class` whenever `bases` contains an *attrs* class.

[`_make_attr_tuple_class('C', ['a', 'b'])`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L266-L284) mints a `CAttributes` tuple subclass with `a` and `b` as properties, and `_Attributes(attrs=(Attribute('a'), Attribute('b')), base_attrs=[], base_attrs_map={})` goes back to the builder.

Back in the constructor, two small settings follow from `these` and from `slots`. [`self._cls_dict`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L694) starts as an empty `{}` rather than a copy of the class dict, because nothing is being rebuilt — it will accumulate only what attrs adds. And [`self._delete_attribs = not bool(these)`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L716) is `False`: when you supply fields via `these`, attrs promises not to strip anything off your class body later. `__attrs_attrs__` and `__attrs_props__` are [stashed in the dict](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L723-L724), and because `props.on_setattr_hook` is `None` rather than one of the three recognized hooks, [the convert/validate pruning branch](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L731-L756) is skipped entirely — there was nothing to prune.

## Four comparison methods, written by hand

[`add_repr`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1004-L1012) and [`add_eq`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1150-L1162) queue their scripts exactly as in chapter 3 — the repr with its thread-local recursion guard, the eq with its `other.__class__ is not self.__class__: return NotImplemented` preamble and the two-term `and` chain over `self.a` and `self.b` — and `__ne__` is dropped straight into the dict as [the shared function](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1730-L1739).

Then something chapter 3 never did: [`add_order`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1164-L1172). `order` resolved to `True` back in chapter 7, so [`_make_order`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1779-L1832) produces four real closures — not source strings — over a shared [`attrs_to_tuple`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1785-L1794) helper that builds a tuple of the ordered field values. Each of the four is passed through [`_add_method_dunders_unsafe`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1226-L1238), which stamps `__module__`, `__qualname__` (`C.__lt__`, `C.__le__`, …) and a generated docstring, and lands in `cd` immediately rather than in the snippet queue.

The type check in [`__lt__`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1796-L1803) is the same exact-identity test as `__eq__`: a subclass instance, or anything else, gets `NotImplemented`. For equality that degrades politely to `False`; for ordering, when both sides return `NotImplemented`, Python raises `TypeError: '<' not supported between instances of …`.

> **For the owner:** `make_class` enables ordering by default (`attr.s` resolves `order` to mirror `eq`), while `define` does not. The generated `__lt__`/`__le__`/`__gt__`/`__ge__` return `NotImplemented` unless both operands are the exact same class, so comparing a subclass instance to a base instance raises `TypeError` rather than ordering them; pass `order=False` to `make_class` if you don't want these four methods.

[`add_setattr`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1174-L1186) then walks both fields looking for `a.on_setattr or self._on_setattr`. Both are `None`, `sa_attrs` stays empty, and it returns on the spot. `C` gets no custom `__setattr__`: assignment is a plain write into the instance `__dict__`. Finally, `is_hashable` is `False` and the hashability is `UNHASHABLE`, so [`make_unhashable`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1066-L1068) writes `__hash__ = None`.

## The two-line initializer

[`add_init`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1085-L1108) calls [`_make_init_script`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L2030-L2096) with `frozen=False`, `slots=False`, `cache_hash=False` and `cls_on_setattr=None`, so `needs_cached_setattr` stays `False` and both fields survive the filter. Inside `_attrs_to_init_script`, [`_determine_setters(frozen=False, slots=False, base_attr_map={})`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L2183-L2184) falls through to the last line — when a class isn't frozen, `slots` doesn't matter at all — and returns `((), _assign, _assign_with_converter)`.

Both fields are mandatory with no factory and no converter, so each takes [the final `else`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L2360-L2377): the alias goes into `args` as a bare positional parameter, and [`_assign('a', 'a', False)`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L2116-L2124) returns the string `'self.a = a'`. There are no validators to append, no post-init call, no hash-cache line, no `BaseException.__init__`. What [comes out](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L2442-L2448) is exactly:

```
def __init__(self, a, b):
    self.a = a
    self.b = b
```

`annotations` is just `{'return': None}`, because [the annotation step](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L2379-L2384) needs `a.type` to be non-`None` and these fields have no types. The globs, however, are not empty: [`_make_init_script` copies in](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L2085-L2087) `sys.modules[cls.__module__].__dict__`, which is why the trace shows `SomeClass`, `Factory`, `NOTHING` and `_SRC` sitting in the namespace of a function that references none of them. Same snapshot semantics as chapter 5, same blast radius.

## Two protocols, added because the slots were empty

[`_has_own_attribute(C, '__replace__')`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L313-L317) is `False`, so [`add_replace`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1110-L1116) installs a `__replace__` that forwards to [`evolve`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L636-L644) — meaning `copy.replace(C('foo','bar'), b='baz')` will go back through `__init__` with the fields' aliases, not poke at the instance dict. `__match_args__` is likewise absent, so [`add_match_args`](https://github.com/python-attrs/attrs/blob/8f767776326faaed11e6c2974798787f6e19b343/src/attr/_make.py#L1118-L1123) collects every `init` and non-`kw_only` field into `('a', 'b')`.

The builder is now loaded: three queued snippets, four ordering functions, `__ne__`, `__hash__ = None`, `__replace__`, `__match_args__`, `__attrs_attrs__`, `__attrs_props__`. Nothing has been compiled and nothing has touched the class object yet.

> **Leaves as:** a `_ClassBuilder(cls=C)` holding `_cls_dict` with `__attrs_attrs__`, `__attrs_props__`, `__ne__`, `__lt__`/`__le__`/`__gt__`/`__ge__`, `__hash__ = None`, `__replace__`, `__match_args__ = ('a', 'b')`, plus three unevaluated snippets whose init script is `def __init__(self, a, b):\n    self.a = a\n    self.b = b\n`
